# T2 OpenCV 4.10 本地依赖设计

**日期：** 2026-07-16  
**主线：** T2 感知算法与元数据  
**状态：** 已实施并验证

## 1. 背景与目标

当前 Meson 通过系统的 `opencv4` pkg-config 依赖构建可选的 OpenCV 功能；`ssv-track` 的 GMC 和相关单测会因系统是否安装 OpenCV 而改变行为。本阶段将 OpenCV 固定为 Ubuntu 官方 pool 的 4.10 二进制包，并由仓库脚本下载、解包和链接。

目标如下：

- 默认 `SSV_OPENCV=enabled` 时，`./ssv build` 首次执行自动下载所需 OpenCV 包，不调用 `apt`。
- `SSV_OPENCV=disabled` 时不下载、不探测或链接系统 OpenCV，并使用 GMC 的无 OpenCV 退化路径。
- enabled 模式的编译、单测和运行时只使用 `.deps` 中的 OpenCV 4.10。
- 只携带项目实际需要的 OpenCV 模块及其 OpenCV 内部递归依赖；通用系统 ABI 运行库仍由宿主提供。
- 缓存可复用，错误或不完整的包和解包目录必须阻止构建继续。

## 2. 非本阶段范围

- 不重新编译 OpenCV，也不把 OpenCV 静态链接进项目插件。
- 不下载或替换 `glibc`、`libstdc++`、CUDA、图形驱动、图像编解码库、TBB 等非 OpenCV 通用系统依赖。
- 不引入 `contrib`、`highgui`、`videoio` 等当前代码未使用的 OpenCV 模块；`dnn` 仅作为 `video` 的运行时递归依赖携带，不使用其开发接口。
- 不修改推理后端；YOLO 推理继续使用 ONNX Runtime。

## 3. 固定包集合

下载源根目录为：

```text
https://archive.ubuntu.com/ubuntu/pool/universe/o/opencv/
```

固定 OpenCV Debian 修订为 `4.10.0+dfsg-5ubuntu1`。该修订要求的 glibc ABI 与当前宿主兼容。脚本根据 `uname -m` 选择 `amd64` 或 `arm64` 包；不使用仅适用于特定 x86 CPU 的 `amd64v3` 包。

每个支持架构下载以下 13 个包，文件名中的 `<arch>` 为 `amd64` 或 `arm64`：

| 模块 | 开发包 | 运行时包 | 保留原因 |
| --- | --- | --- | --- |
| core | `libopencv-core-dev_4.10.0+dfsg-5ubuntu1_<arch>.deb` | `libopencv-core410_4.10.0+dfsg-5ubuntu1_<arch>.deb` | `cv::Mat` 等基础类型 |
| imgproc | `libopencv-imgproc-dev_4.10.0+dfsg-5ubuntu1_<arch>.deb` | `libopencv-imgproc410_4.10.0+dfsg-5ubuntu1_<arch>.deb` | 灰度化和角点处理 |
| video | `libopencv-video-dev_4.10.0+dfsg-5ubuntu1_<arch>.deb` | `libopencv-video410_4.10.0+dfsg-5ubuntu1_<arch>.deb` | 光流跟踪 |
| calib3d | `libopencv-calib3d-dev_4.10.0+dfsg-5ubuntu1_<arch>.deb` | `libopencv-calib3d410_4.10.0+dfsg-5ubuntu1_<arch>.deb` | 仿射变换估计 |
| features2d | `libopencv-features2d-dev_4.10.0+dfsg-5ubuntu1_<arch>.deb` | `libopencv-features2d410_4.10.0+dfsg-5ubuntu1_<arch>.deb` | `calib3d` 的 OpenCV 递归依赖 |
| flann | `libopencv-flann-dev_4.10.0+dfsg-5ubuntu1_<arch>.deb` | `libopencv-flann410_4.10.0+dfsg-5ubuntu1_<arch>.deb` | `features2d` 和 `calib3d` 的 OpenCV 递归依赖 |
| dnn | 非本阶段不下载开发包 | `libopencv-dnn410_4.10.0+dfsg-5ubuntu1_<arch>.deb` | `libopencv-video410` 的运行时递归依赖 |

不下载 `libopencv-dev` 总包，避免将全部 OpenCV 模块作为依赖引入。

## 4. 本地目录与构建链路

```mermaid
flowchart LR
    A[Ubuntu 官方 pool] --> B[.deps/downloads/opencv 原始 deb 包]
    B --> C[.deps/opencv/usr 本地 SDK]
    C --> D[.deps/opencv/lib/pkgconfig/opencv4.pc]
    D --> E[Meson 编译插件与单测]
    C --> F[运行时 LD_LIBRARY_PATH]
    E --> F
```

目录固定为：

```text
.deps/
├── downloads/
│   └── opencv/
│       └── libopencv-*.deb
└── opencv/
    ├── usr/include/opencv4/
    ├── usr/lib/<multiarch>/
    └── lib/pkgconfig/opencv4.pc
```

`scripts/build.sh` 是 OpenCV 下载、校验、解包和 pc 生成的唯一实现位置；不新增 OpenCV helper 脚本。`scripts/lib.sh` 仅保留运行时所需的根目录默认值，并从其 `usr/lib/*` 中发现实际存在的 multiarch 动态库目录。`scripts/build.sh` 仅在 `SSV_OPENCV=enabled` 时于 Meson 配置前执行 OpenCV 准备步骤：

1. 检查 `.deps/opencv/usr/` 是否同时具备所需头文件、无版本链接名和版本化运行时库；完整时直接复用。
2. 缓存不存在时将固定包集下载到 `.deps/downloads/opencv/`；缓存包须通过 `dpkg-deb` 的包名、版本和架构元数据检查。
3. 将全部包解压至临时目录；检查必需文件后，保留其 `usr` 原始目录层级并收口到 `.deps/opencv/`。
4. 在 `.deps/opencv/lib/pkgconfig/opencv4.pc` 生成本地 pkg-config 描述，`prefix` 指向 `.deps/opencv`，`Libs` 列出六个直接开发模块，并显式链接宿主提供的 `protobuf`、`TBB`、`BLAS`、`LAPACK` 系统库；`dnn` 仅作为 `video` 的版本化运行时依赖随包携带，不作为 OpenCV 开发包单独链接。
5. 将 `.deps/opencv/lib/pkgconfig` 置于 `PKG_CONFIG_PATH` 的最前方，再执行 Meson 配置。

临时解包、包元数据或必需文件检查任一失败时，脚本以明确错误终止，不保留可被下一次构建误判为完整的 SDK。

### 4.1 脚本配置接口收敛

OpenCV 对外只保留两个环境变量：

- `SSV_OPENCV=enabled|disabled`：构建开关；默认值和合法性校验均由 `scripts/build.sh` 处理。
- `SSV_OPENCV_ROOT`：本地 SDK 根目录的高级覆盖入口，默认 `.deps/opencv`；`scripts/lib.sh` 保留该默认值，以便构建、单测和运行时使用同一个目录。

`4.10.0`、`4.10.0+dfsg-5ubuntu1`、Ubuntu pool URL、Deb 包架构、multiarch 目录、pkg-config 目录和库目录均为 `ensure_opencv()` 的内部局部实现细节，不声明为环境变量，也不在 `.env.example` 中公开。构建完成前，`build.sh` 使用局部 `pc_dir` 和 `lib_dir` 配置 `PKG_CONFIG_PATH`、`LD_LIBRARY_PATH`；运行时由 `lib.sh` 扫描 `$SSV_OPENCV_ROOT/usr/lib/*` 并仅加入存在的目录。

## 5. 编译与运行时约束

- 根 `meson.options` 提供 `opencv=enabled|disabled`。`./ssv build` 把 `SSV_OPENCV` 传给该 option；enabled 时将 `.deps/opencv/lib/pkgconfig` 置于 `PKG_CONFIG_PATH` 最前，且 `dependency('opencv4')` 必须成功；disabled 时 Meson 不探测 OpenCV。
- `ssv-track` 和 `gst/tests` 根据 `opencv_enabled` 设置 `SSV_HAS_OPENCV`；disabled 时保留 GMC identity/安全退化路径。
- enabled 模式的本地 pc 文件 include 路径为 `.deps/opencv/usr/include/opencv4`，库路径为 `.deps/opencv/usr/lib/<multiarch>`。
- enabled 模式的脚本共享运行环境、Meson 单测环境均将该库目录放在 `LD_LIBRARY_PATH` 的前部。
- OpenCV 动态库的非 OpenCV `DT_NEEDED` 依赖继续由宿主系统提供。宿主须满足包所要求的 SONAME 和 ABI 符号版本，例如 `GLIBC_2.x`、`GLIBCXX_3.4.x`。

## 6. 错误处理与验收

| 场景 | 预期行为 |
| --- | --- |
| 首次默认 `./ssv build` | 自动下载 13 个包、解包、生成本地 pc 后继续构建 |
| 后续构建 | 复用 `.deps/downloads/opencv/` 与完整的 `.deps/opencv/usr/`，不重复下载 |
| 下载包损坏、版本错误或架构不匹配 | 构建失败，并报告对应文件和元数据检查结果 |
| 解包结果不完整 | 构建失败，不将临时目录作为本地 SDK 使用 |
| 系统未安装 OpenCV | `./ssv build` 仍能使用本地 SDK 完成构建 |
| 系统安装其他版本 OpenCV | 编译与运行仍优先使用 `.deps/opencv/usr/` |
| enabled GMC 单测 | `meson test -C build` 以本地 OpenCV 启用状态执行 |
| `SSV_OPENCV=disabled ./ssv build` | 不下载、不探测系统 OpenCV，GMC 以无 OpenCV 退化路径构建 |

实施完成后，按改动范围至少运行：

```bash
./ssv build
meson test -C build
```

若宿主的通用 ABI 运行库不满足 OpenCV 4.10 包要求，验证结果需明确报告缺失的动态库或符号版本。

本次验证记录（2026-07-17）：默认 `./ssv build` 首次下载并解包 13 个 `4.10.0+dfsg-5ubuntu1` 包成功；默认 enabled 与 `SSV_OPENCV=disabled` 两种模式的 `meson test -C build` 均通过（1/1）；`bash tests/ssv_cli_test.sh` 通过；第二次 enabled `./ssv build` 未重复下载；`ldd` 显示 enabled 模式的 OpenCV 相关库均解析到 `.deps/opencv/usr/lib/x86_64-linux-gnu`。
