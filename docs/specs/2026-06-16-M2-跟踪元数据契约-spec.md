# M2 跟踪元数据契约 spec

## 背景

`M2/B` 属于 `T2` 感知算法与元数据主线，目标是在 `M1/B` 检测元数据契约的基础上固化跟踪结果进入 `ssv_meta` 后的字段语义和状态流转规则。`M1/B` 已定义了 `track_id` 的基本语义和 `class_id` / `track_id` 的归一化规则；但跟踪模块的输出不仅仅是 "检测 + 一个 ID"，还包括跟踪状态（新目标/持续匹配/丢失）、遮挡标志等业务语义，这些在 `M1/B` 阶段尚未纳入契约。

现有 `test_detection_store_tracking_flow` 已覆盖最基本的 `set → take_for_tracking → set_tracked → take` 路径，但缺少以下覆盖：多个检测各自写回不同 `track_id`、状态机边界（不允许覆盖未发布跟踪数据）、`set_tracked` 路径对无效检测的过滤、跟踪状态和遮挡标志的传播，以及 overlay 在 `take` 后是否还能读出数据。

## 目标

1. 明确 `track_id`、`track_state`、`occluded` 在检测、跟踪、发布、overlay 之间的完整数据交接契约。
2. 引入 `SsvTrackState` 枚举（NEW/MATCHED/LOST/DEAD）表达跟踪的阶段语义。
3. 利用 `track-thresh` 属性决定遮挡标志，使该属性从"定义未使用"变为生效。
4. 固化 `SsvDetectionStore` 状态机在跟踪场景下的边界行为。
5. 补齐 `gst/tests` 对跟踪元数据边界行为的覆盖。
6. 在 overlay 显示中增加 `track_id`、`track_state` 和 `occluded`。

## 范围

本阶段包含：

1. `track_id`、`track_state`、`occluded` 字段语义与数据交接契约：写入方、读取方、存储方的职责。
2. `SsvTrackState` 枚举和跟踪阶段语义。
3. `track-thresh` 属性在 IoU tracker 中实际生效——用于遮挡判定。
4. `SsvDetectionStore` 状态机在跟踪场景下的边界测试。
5. 跟踪状态、遮挡标志经过 store 流转后正确保持的测试。
6. 无效 `track_state` 的归一化测试。
7. overlay 显示标签增加 `track_id`、状态缩写和遮挡标志，并保证标签使用的字符都有 bitmap 字形。
8. `ssvpub` 将 `track_state` 和 `occluded` 透传到 Redis JSON 消息，作为 T3/T4 事件链路的输入字段。

本阶段不包含：

1. 不规定跟踪算法策略。IoU 匹配、速度预测、类别约束、轨迹保留策略属于 `ssvtrack` 内部实现，不属于元数据契约。
2. 不进行真实跟踪器多帧匹配验证。mock 跟踪 / 真实跟踪的 smoke 验证属于 `M2/C`。
3. 不冻结完整 Redis 事件 schema。`M2/B` 只要求现有 detection JSON 透传 `track_id`、`track_state`、`occluded`，完整事件类型、严重级别、证据字段和状态字段仍由 `M3/B` 冻结。
4. 不改变 pipeline runner、脚本职责或运行模式。
5. 不引入外部跟踪框架或重写跟踪插件。
6. 不改动 bbox 坐标格式（保持 `x1y1x2y2` 归一化坐标，与 `M1/B` 一致）。

## 跟踪状态机

每个目标轨迹在生命周期中经历以下阶段：

```
检测进入跟踪 ──→ NEW (0) ← 轨迹创建帧，首次匹配
                    │
                    ↓
               MATCHED (1) ← 后续帧持续匹配
                    │
               ┌───┘
               ↓
          time_since_seen > 0 且未匹配
                    │
                    ↓
               LOST (2) ← 目标在当前帧未匹配到检测
               （无对应检测框输出）
                    │
         超过 track-buffer 帧未匹配
                    │
                    ↓
               DEAD (3) ← 轨迹被移除
               （无对应检测框输出）
```

其中 NEW 和 MATCHED 有对应的检测框输出，LOST 和 DEAD 是轨迹级状态（无对应检测框）。下游消费者（事件判定模块）可以根据 NEW → MATCHED 的转换判断轨道是否稳定，避免在第一帧就触发事件。

## 核心约束

### track_id

```
track_id = -1       表示未跟踪或没有稳定轨迹
track_id >= 1       由 ssvtrack 分配的轨迹 ID（连续正整数，非零）
```

`track_id` 的类型是 `int`，在 `SsvDetection` 中默认初始化为 `-1`。任何进入 `SsvDetectionStore` 的 `track_id < -1` 都会被归一化为 `-1`。

`ssvtrack` 的 `IoUTracker` 新轨迹 ID 从 `1` 开始递增；`mock-track` 模式的 ID 也从 `1` 开始递增。因此 `track_id == 0` 是一个不合法状态，不在任何路径中出现。

### track_state

```
track_state = 0 (NEW)      新轨迹，第一帧出现
track_state = 1 (MATCHED)  持续匹配的轨迹
track_state = 2 (LOST)     轨迹丢失（无对应检测框）
track_state = 3 (DEAD)     轨迹已移除（无对应检测框）
```

`track_state` 的类型是 `int`，在 `SsvDetection` 中默认初始化为 `0`（NEW）。对于尚未跟踪的检测（`track_id = -1`），`track_state` 也为 `0`（NEW），表示"等待跟踪"。任何进入 `SsvDetectionStore` 的 `track_state < 0` 或 `track_state > 3` 都会被归一化为 `0`（NEW）。

### occluded

```
occluded = true   检测匹配成功但置信度低于 track-thresh，可能处于遮挡状态
occluded = false  检测匹配成功且置信度不低于 track-thresh，或尚未跟踪
```

`occluded` 的类型是 `bool`，默认值为 `false`。它由 `ssvtrack` 在匹配时根据 `track-thresh` 属性决定。

## 字段契约

### SsvDetection（跟踪相关部分）

| 字段 | 语义 | 规则 |
| --- | --- | --- |
| `track_id` | 跟踪 ID | `-1` = 未跟踪；非负值由 `ssvtrack` 分配；`< -1` 归一化为 `-1` |
| `track_state` | 跟踪阶段 | `0`=NEW, `1`=MATCHED, `2`=LOST, `3`=DEAD；`<0` 或 `>3` 归一化为 `0` |
| `occluded` | 遮挡标志 | `false` = 正常跟踪或未跟踪；`true` = 匹配但置信度低于 `track-thresh` |

### SsvFrameDetections（无变更）

`M1/B` 已冻结的字段语义保持不变；`M2/B` 只增加 `track_state` 和 `occluded` 的流转契约。

### SsvOverlayFrame

`SsvOverlayFrame` 是 `SsvFrameDetections` 的副本结构，用于 `peek_latest()` 非消耗读取。它与 `SsvFrameDetections` 保持相同字段语义，包括新增的跟踪字段。

## 数据交接契约

### 写入方：`ssvtrack`

1. `ssvtrack` 通过 `SsvDetectionStore::take_for_tracking()` 获取未跟踪检测。
2. 对于匹配到轨迹的检测：
   - 写入对应轨迹的 `track_id`。
   - `track_state` = `MATCHED`（已有轨迹）或 `NEW`（新创建轨迹）。
   - `occluded` = `confidence < track-thresh`。
3. 对于新检测（未匹配任何轨迹）：
   - 分配新 `track_id`（从 `1` 开始递增）。
   - `track_state` = `NEW`。
   - `occluded` = `false`。
4. `mock-track` 模式下，每帧每个检测获得一个独立的递增 `track_id`，全部标记为 `NEW` + `occluded=false`。
5. 写回调用 `SsvDetectionStore::set_tracked()`。

### 存储方：`SsvDetectionStore`

1. `set()` 写入检测结果并进入 `HAS_DETECTIONS` 状态（可被 `take_for_tracking` 消费）。
2. `set()` 在 `HAS_TRACKS` 状态下**被跳过**，不覆盖未发布的跟踪数据。
3. `take_for_tracking()` 在 `HAS_DETECTIONS` 状态下返回数据并回到 `EMPTY`；在非 `HAS_DETECTIONS` 状态下返回空。
4. `set_tracked()` 写入跟踪结果并进入 `HAS_TRACKS` 状态（可被 `take` 消费）。
5. `take()` 在 `HAS_TRACKS` 或 `HAS_DETECTIONS` 状态下返回数据并回到 `EMPTY`；在 `EMPTY` 状态下返回空。
6. `peek_latest()` 返回当前存储的 overlay 副本而不改变状态。
7. `set()` 和 `set_tracked()` 都执行 `normalize_frame_detections()` 过滤无效检测并归一化所有字段。

### 读取方：`ssvpub`

1. `ssvpub` 通过 `SsvDetectionStore::take()` 获取已跟踪检测结果。
2. 将 `track_id`、`track_state`、`occluded` 按原值序列化到 Redis JSON 消息的每个检测中。
3. Redis JSON 中每个 detection 至少包含 `class`、`class_id`、`confidence`、`bbox`、`track_id`、`track_state`、`occluded`。
4. 不修改这些字段的值。

### 读取方：`ssvoverlay`

1. `ssvoverlay` 通过 `SsvDetectionStore::peek_latest()` 非消耗读取最新检测结果。
2. 标签格式：
   - 无 track_id：`class_name confidence`
   - 有 track_id（默认 MATCHED 无非遮挡）：`class_name #id confidence`
   - NEW 状态：`class_name #id[N] confidence`
   - 遮挡状态（MATCHED + occluded）：`class_name #id[O] confidence`
   - NEW + 遮挡：`class_name #id[No] confidence`
3. 标签中出现的字符必须能被内置 `FONT_5X7` 渲染。当前格式依赖的 `#`、`[`、`]` 必须有非空字形，不能回退为空格。

## 状态机边界规则

```
EMPTY ──set()─────→ HAS_DETECTIONS ──take_for_tracking()──→ EMPTY
  ↑                      ↓                   │
  │                      │       set_tracked()│
  │                      ↓                   ↓
  └────── take() ←── HAS_TRACKS ←────────────┘
```

| 操作 | 原始状态 | 结果状态 | 行为 |
| --- | --- | --- | --- |
| `set()` | EMPTY | HAS_DETECTIONS | 正常写入检测数据 |
| `set()` | HAS_DETECTIONS | HAS_DETECTIONS | 覆盖上一次检测数据（新检测覆盖旧检测） |
| `set()` | HAS_TRACKS | HAS_TRACKS | **跳过**，不覆盖未发布跟踪数据 |
| `take_for_tracking()` | HAS_DETECTIONS | EMPTY | 返回检测数据 |
| `take_for_tracking()` | EMPTY | EMPTY | 返回空 |
| `take_for_tracking()` | HAS_TRACKS | HAS_TRACKS | 返回空 |
| `set_tracked()` | EMPTY | HAS_TRACKS | 正常写入跟踪数据 |
| `set_tracked()` | HAS_DETECTIONS | HAS_TRACKS | 正常写入跟踪数据（覆盖尚未使用的检测） |
| `set_tracked()` | HAS_TRACKS | HAS_TRACKS | 覆盖上一次跟踪数据（正常连续帧跟踪） |
| `take()` | HAS_TRACKS | EMPTY | 返回跟踪数据 |
| `take()` | HAS_DETECTIONS | EMPTY | 返回检测数据（兼容无跟踪模式） |
| `take()` | EMPTY | EMPTY | 返回空 |
| `peek_latest()` | 任意 | 不变 | 返回 overlay 副本 |

## 防御规则

1. `track_id < -1` 在 `ssv_normalize_detection()` 中被归一化为 `-1`。
2. `track_id = -1` 是有效的未跟踪默认值，不应被视为非法。
3. `track_state < 0` 或 `track_state > 3` 在 `ssv_normalize_detection()` 中被归一化为 `0`（NEW）。
4. `occluded` 是 `bool` 类型，无需归一化。
5. `set_tracked()` 同样调用 `normalize_frame_detections()`，因此通过 `ssvtrack` 写回的非法检测仍会被过滤，`track_state` 和 `track_id` 的非法值也会被归一化。
6. 空检测列表的 `SsvFrameDetections` 可以被正常写入 `set_tracked()` 并推进状态机。

## 测试验收

`gst/tests` 应覆盖以下行为：

1. **Track ID 写回**：多个检测各自获得不同 `track_id`、`track_state`、`occluded`，经过完整 `set → take_for_tracking → set_tracked → take` 后正确保持。
2. **未跟踪默认值保持**：`track_id = -1`、`track_state = NEW`、`occluded = false` 在 store 流转中不被污染。
3. **状态机跳过**：`set()` 在 `HAS_TRACKS` 状态被跳过，之后 `take()` 仍能取到原跟踪数据和状态。
4. **take_for_tracking 边界**：在非 `HAS_DETECTIONS` 状态下返回空。
5. **take 边界**：在 `EMPTY` 状态下返回空。
6. **set_tracked 过滤**：即使调用 `set_tracked`，其中包含的无效检测仍被过滤，有效检测的跟踪状态不变。
7. **空检测 set_tracked**：空检测列表仍然正确推进到 `HAS_TRACKS` 状态。
8. **overlay 独立副本**：`take()` 消耗数据后，`peek_latest()` 仍有 overlay 数据和跟踪状态。
9. **track_state 归一化**：`track_state < 0` 或 `track_state > 3` 被归一化为 `NEW`。
10. **Redis 跟踪字段透传**：`ssvpub` 构造的 JSON payload 中每个 detection 包含 `track_state` 和 `occluded`，字段值与 `SsvDetection` 一致。
11. **overlay 字形覆盖**：`class_name #id[No] confidence` 标签中使用的字符都被 `FONT_5X7` 支持，尤其是 `#`、`[`、`]`。

建议验证命令：

```bash
./ssv build
meson test -C build
```

## 退出标准

1. `track_id`、`track_state`、`occluded` 字段语义被文档化并有测试覆盖。
2. `SsvTrackState` 枚举定义清晰（NEW/MATCHED/LOST/DEAD），边界值归一化正确。
3. `track-thresh` 属性实际生效，用于 IoU tracker 的遮挡判定。
4. `SsvDetectionStore` 状态机在跟踪场景下的边界行为有测试覆盖。
5. overlay 标签显示 `track_id` 和状态/遮挡标志，且相关字符都有 bitmap 字形。
6. Redis detection JSON 透传 `track_id`、`track_state`、`occluded`，供后续 T3/T4 消费。
7. 所有测试通过 `./ssv build && meson test -C build`。
8. 后续 `M2/C` 添加 mock/真实跟踪 smoke 时不需要修改 `ssv_meta` 字段契约或状态机逻辑。
