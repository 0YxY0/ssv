# T1/T2 运行时与模块结构收口规范

## 文档定位

本文将 VA-API/ONNX Runtime 单路加速、runner 深化、inference runtime snapshot、inference
接口迁移、track/common seam 和 latest-frame scheduler 收敛为一组运行时与结构契约。

“结构整理”不是独立的透传重命名：每次目录迁移都必须同时表达真实依赖方向、资源所有权和测试
边界。运行行为和公开 GStreamer 属性保持兼容，除非本规范明确说明。

## 目标

1. C++ runner 成为唯一生产 pipeline 入口；shell 只负责配置、依赖快照、环境交接和命令分发。
2. inference 以 owning runtime snapshot、统一 Provider resolver 和 session pool 对外报告能力；
   runner 不依赖 backend 私有类型。
3. latest-frame 调度从 SsvInferenceService 中抽为可独立测试的 SsvLatestFrameScheduler。
4. runner、gst/ssv-infer、gst/ssv-track 和 gst/ssv-common 的目录反映 core、adapter、plugin、
   public 和 tests 的真实职责。
5. 日志通过有界、可关闭、可替换 sink 的 SsvEventLog 输出结构化事件；fatal 路径保留最小
   stderr 兜底。
6. 依赖 profile、Provider 顺序、TensorRT/CUDA ABI、OpenCV workspace 和运行库闭包由
   ssv_deps_prepare 解析并写入成功快照，构建和运行使用同一快照。

## 运行时契约

### Configuration and pipeline plan

- SsvConfig 负责 YAML 解析、语义校验和显式 CLI override。
- SsvPipelinePlan 是能力探测与配置解析后的纯值计划，包含 decode、display、analysis、provider
  和 fallback 决策。
- SsvPipelineBuilder 只根据 plan 创建 GStreamer 元素和 branch；不重新解析 YAML。
- SsvRunAttempt 拥有一次 pipeline 尝试的资源和状态；SsvRunner 负责重试/回退和退出结果。

### Inference runtime

- SsvInferenceService 公开稳定 service interface，内部组合 engine、analysis frame pool、
  runtime snapshot 和 scheduler。
- SsvInferenceRuntimeSnapshot 以 owning value 暴露 profile、Provider、model/cache 和诊断信息；
  调用方不能持有 resolver 或 session pool 的借用引用。
- Provider resolver 必须返回严格的顺序和 ABI 匹配结果；禁止静默跨 accelerator 回退。
- SsvLatestFrameScheduler 只有一个 worker、一个 in-flight 和一个 pending 任务。新 pending 替换
  旧 pending；cancel(source_id) 和 stop() 都必须唤醒提交方并等待 worker 退出。

### Dependency and build

- ./ssv build --profile auto|cpu|nvidia|intel|amd 解析 profile。
- ssv_deps_prepare 解析来源、版本、Provider 和 ABI，写入 build/ssv-deps.env。
- ssv_deps_load_runtime 只加载成功快照，不能扫描 Python wheel 或隐式 SDK 路径。
- Meson 只消费 onnxruntime_profile、onnxruntime_dependency_signature、tensorrt_mode
  和显式 runtime/pkg-config path。
- managed artifacts 位于 .deps workspace；未知或受保护目录不得被清理。

## 目录与依赖方向

    gst/ssv-common/
      include/                 stable metadata/config values
      config/ frame/ meta/    implementation ownership
      tests/                  common contract tests

    gst/ssv-infer/
      public/                  service and model contracts
      core/                    engine, service, scheduler, buffers
      model/                   model contract and YOLO parser
      backends/                ONNX Runtime and TensorRT providers
      plugin/                  thin GStreamer adapter
      tests/                   module and provider tests

    gst/ssv-track/
      core/                    BoT-SORT and algorithm values
      adapters/                SSV/GStreamer conversion and geometry
      plugin/                  lifecycle and metadata adapter
      tests/                   tracker and adapter contracts

    runner/
      pipeline/                capability, plan, builder and topology
      runtime/                 attempts, fallback and event adapter
      display/                 GTK lifecycle and overlay attachment
      observability/           event log and sinks

依赖方向固定为：

    runner → public inference / common values
    plugin → core or adapter
    adapter → common values and algorithm core
    backend → inference core contracts
    tests → public/test-support seams

生产模块不得反向依赖 runner observability、测试 support 或另一个 plugin 的 implementation header。

## 日志契约

- SsvEventLog.create(options, sink) 接收值语义 options 和唯一 owning sink。
- emit(SsvEvent) 是 noexcept 边界；事件序列化、大小上限、flush timeout 和 shutdown timeout
  由 logger 管理。
- SsvLogSink 可替换为 stderr、文件或未来异步 sink；调用方不依赖具体 sink 类型。
- runtime、inference、fallback、display 和 fatal event 使用稳定字段名，耗时统一以可读毫秒
  或明确的计数单位输出。

## 验收标准

- 所有 C++ production/test targets 能由 Meson 重建。
- scheduler、runtime snapshot、pipeline plan/builder、logger、provider 和目录 public seam
  均有独立测试。
- shell 入口通过 bash -n，依赖测试验证 snapshot、ABI、缓存和 workspace 保护。
- CI 安装 GTK development headers 后，./ssv test 可在无 RTSP 配置时完成确定性测试。
- 不保留旧平铺 implementation、旧 shell pipeline 或重复 provider accessor。

## 非本阶段范围

- 不改变 ONNX 模型训练或 wrapper 的推理数值语义。
- 不在 runner 中暴露 TensorRT/ONNX Runtime 私有类。
- 不引入异步 logger 实现；本阶段只固定可替换的同步接口。
- 不将 reports、模型、依赖缓存和运行日志作为仓库交付物。
