# T1/T2 检测展示优化规范

## 文档定位

本文将此前的“最新帧显示与 PTS 展示预测”和“GPU 解码与 GL 显示”两组设计收敛为一个最终契约。
它描述视频观察窗口如何与检测、跟踪结果对齐，不改变 Redis 事件格式、跟踪算法状态或模型输出契约。

旧阶段文档只保留为本地历史材料；本次交付的实现、测试和运行说明以本文和配套 plan 为准。

## 目标

1. 显示分支按媒体 PTS 播放，分析分支按配置的 inference.analysis_fps 抽帧，两个分支都采用
   drop-only 策略，不积压旧帧。
2. 检测、跟踪和展示共享 source_id、generation、PTS 和 duration，展示只消费与当前时间线相容的
   不可变 tracked snapshot。
3. 当显示帧没有对应的推理结果时，使用最近的因果快照；在配置的预测窗口内对框位置做展示专用
   运动预测，预测结果不回写 tracker、Redis 或事件证据。
4. 观察窗口支持 gtkglsink 和 gtksink 两条明确路径。显式选择不可用时失败，auto 才允许记录
   原因后回退。
5. H.264 解码支持 auto、vaapi、nvdec 和 software。显式硬件模式不得静默回退；硬件解码与
   CPU overlay 之间的内存边界必须在 pipeline plan 中可观察。

## 时间线与结果契约

### Source context

- SsvSourceMeta 是单个 source 的 detection mailbox、tracked publication、history 和统计所有者。
- SsvSourceContext 显式持有 source metadata，调用方不再通过隐式全局状态传递 source 生命周期。
- SsvTimelineCursor 在 segment、flush-stop、PTS discontinuity 和 lifecycle reset 时推进 generation；
  不同 generation 的结果不能进入当前显示。

### Frame and snapshot

- SsvFrameTiming 携带 pts、duration 和 generation。
- SsvDetectionFrame 只表示一次推理观察，拥有对应的 SsvAnalysisFrame 引用。
- SsvTrackedFrame 是 immutable publication；SsvTrackedObject.track_id 没有有效 ID 时保持 -1，
  展示层不得伪造 tracker ID。
- latest_tracked_at_or_before(display_pts) 只返回同一 source、同一 generation 且不晚于显示 PTS 的快照。

### Display selection

1. 没有 PTS 的显示帧只计入 no_pts 统计，不消费未来结果。
2. 当前快照的 observation PTS 晚于显示 PTS 时丢弃该候选。
3. 快照过旧或超过 max_horizon_ms 时停止预测并清理 predictor 状态。
4. generation、source 或 PTS 不一致时拒绝候选并记录对应统计。
5. 预测框只写入 SsvOverlayFrame，不改变 SsvTrackedFrame。

## 配置契约

示例配置 config/ssv.example.yaml 的关键字段如下：

| 字段 | 语义 |
| --- | --- |
| sources[0].codec | 当前 source 的编码，现阶段为 h264 |
| sources[0].decode.mode | auto、vaapi、nvdec 或 software |
| sources[0].decode.device | auto、DRM render node 或 CUDA device |
| display.backend | auto、gtkglsink 或 gtksink |
| display.gl_backend | auto、x11 或 wayland |
| display.fps | 显示分支的 drop-only 上限 |
| display.overlay.motion_prediction.enabled | 是否启用展示预测 |
| display.overlay.motion_prediction.max_horizon_ms | 预测最大时间窗口，默认 300 ms |
| inference.analysis_fps | 分析、跟踪和事件发布分支的抽帧上限；0 表示不限流 |

显示 overlay 只负责视频观察窗口绘制。事件发布仍使用 tracked snapshot 的原始 PTS 和墙钟时间戳，
不能使用预测后的框覆盖业务结果。

## 模块边界

- gst/ssv-common：定义 timing、detection、tracked snapshot、timeline 和 source context。
- gst/ssv-infer：提交带 timing 的 inference request，并发布 detection frame。
- gst/ssv-track：消费 detection frame，执行 BoT-SORT/GMC，并发布完整 tracked frame。
- gst/ssv-pub：消费 immutable tracked frame，保持既有 Redis schema。
- gst/ssv-overlay：由 OverlayRuntime 编排 timeline、presentation、predictor 和 renderer；
  GStreamer adapter 只负责 buffer 映射、属性和错误转译。
- runner/display：创建 GTK 窗口、绑定 display timing 和 overlay attachment；不拥有推理状态。
- runner/pipeline：把 decode、display、analysis 三条 branch 的内存与节流策略物化为 plan。

## 验收标准

- latest-frame、因果 PTS 选择、generation reset 和过期预测均有单元测试。
- overlay predictor、presentation、renderer 和 display window 均有独立测试。
- pipeline builder 覆盖 NVDEC、VAAPI、软件回退、gtkglsink 和 gtksink 合同。
- 显示路径不改变 Redis payload、tracker 状态和模型输入。
- Meson、CLI 契约测试和依赖契约测试通过。

## 非本阶段范围

- 不把 overlay 迁移为 GPU 绘制。
- 不在显示层重新运行检测或跟踪。
- 不引入多 source 混流或多路独立窗口调度。
- 不保留旧 shell pipeline 作为第二套生产运行入口。
