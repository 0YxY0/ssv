# T2 检测元数据契约 spec

## 背景

`M1/B` 属于 `T2` 感知算法与元数据主线，目标是冻结检测结果进入公共元数据层后的字段语义和坐标规则。当前 `ssv_meta` 被 `ssvinfer`、`ssvtrack`、`ssvoverlay` 和 `ssvpub` 共同使用，字段契约一旦变化会影响推理输出、跟踪匹配、调试画框和后续事件发布。

本 spec 只定义检测结果进入 `ssv_meta` 后必须满足的公共契约，不规定上游模型推理策略。整帧推理、切片推理、多尺度推理、batch 推理和并行推理都可以作为上游实现方式存在，但进入 `SsvDetection` 前必须完成坐标反算、过滤和去重。

## 目标

1. 固化 `SsvDetection` 和 `SsvFrameDetections` 的字段语义。
2. 明确 bbox 使用原始视频帧坐标系下的归一化左上右下坐标。
3. 明确非法值、轻微越界坐标和默认值的防御规则。
4. 为 `ssvtrack`、`ssvoverlay`、`ssvpub` 提供稳定输入。
5. 补齐 `gst/tests` 对元数据基本行为和防御规则的覆盖方向。

## 范围

本阶段包含：

1. `ssv_meta` 检测字段语义。
2. `SsvDetectionStore` 接收检测结果前后的规范化和过滤规则。
3. mock 推理和真实推理输出进入 `ssv_meta` 前的一致性要求。
4. `gst/tests` 中元数据字段、bbox 和 store 流转的基础测试。

本阶段不包含：

1. 不规定推理策略。`letterbox`、resize、padding、tile、batch、多尺度和并行推理属于上游推理模块职责。
2. 不规定模型类别体系。`class_id` 与 `class_name` 的具体含义由模型和 label map 决定。
3. 不冻结 Redis 事件 schema。`M1/B` 只保证检测字段稳定，事件消息格式由 `M3/B` 冻结。
4. 不实现安全帽专用模型训练、导出或精度评估。
5. 不改变 pipeline runner、脚本职责或运行模式。

## 核心约束

任何进入 `SsvDetection` 的 bbox 必须已经转换为原始视频帧坐标系下的归一化左上右下坐标：

```text
x1, y1, x2, y2: 原始视频帧坐标系，归一化范围 [0,1]
```

如果上游使用 `letterbox`，必须在进入 `ssv_meta` 前减去 padding 并反算到原始视频帧坐标系。如果上游使用 tile 或多尺度推理，必须在进入 `ssv_meta` 前完成 tile offset 合并、多尺度坐标合并和全局去重。

## 字段契约

### SsvFrameDetections

| 字段 | 语义 | 规则 |
| --- | --- | --- |
| `frame_id` | pipeline 内递增帧编号 | 用于日志、追踪和事件关联；不要求全局唯一 |
| `source_id` | 视频源标识 | 默认可为空字符串；多路输入时上游必须填入稳定值 |
| `detections` | 当前帧最终检测列表 | 进入列表前应完成推理后处理、坐标反算、过滤和去重 |

### SsvDetection

| 字段 | 语义 | 规则 |
| --- | --- | --- |
| `class_name` | 类别名称 | 例如 `person`、`helmet`、`no_helmet`；空字符串表示未知但不推荐 |
| `confidence` | 检测置信度 | 有限浮点数，范围 `[0,1]` |
| `x1` | bbox 左上角 x | 原始视频帧坐标系归一化坐标 |
| `y1` | bbox 左上角 y | 原始视频帧坐标系归一化坐标 |
| `x2` | bbox 右下角 x | 原始视频帧坐标系归一化坐标，必须大于 `x1` |
| `y2` | bbox 右下角 y | 原始视频帧坐标系归一化坐标，必须大于 `y1` |
| `class_id` | 模型类别 ID | `-1` 表示未设置；非负值由模型 label map 解释 |
| `track_id` | 跟踪 ID | `-1` 表示尚未跟踪或没有稳定轨迹；非负值由 `ssvtrack` 写入 |

## 防御规则

检测结果进入 `SsvDetectionStore` 前应统一执行规范化和过滤：

1. `confidence` 必须是有限浮点数且位于 `[0,1]`，否则丢弃该检测。
2. `x1`、`y1`、`x2`、`y2` 必须是有限浮点数，否则丢弃该检测。
3. bbox 坐标允许轻微越界，先 clamp 到 `[0,1]`。
4. clamp 后如果 `x2 <= x1` 或 `y2 <= y1`，丢弃该检测。
5. `class_id` 可以是 `-1` 或非负整数；其他负数归一为 `-1`。
6. `track_id` 可以是 `-1` 或非负整数；其他负数归一为 `-1`。
7. `class_name` 保持当前固定长度数组承载方式；上游应使用短类别名，超长名称按 C 字符串写入规则截断。

这些规则应同时适用于 mock 推理和真实模型推理，避免不同路径产生不同字段语义。

## 下游兼容要求

`ssvtrack` 只能依赖归一化 bbox、`class_id`、`confidence` 和可选 `track_id` 默认值，不解释模型预处理方式。

`ssvoverlay` 只能按当前帧显示尺寸将归一化 bbox 乘回像素坐标，不反推 `letterbox` 或 tile 信息。

`ssvpub` 在 `M1/B` 阶段只消费稳定检测字段，不在本阶段冻结 Redis 事件 schema。现有输出中的 `bbox` 应继续表达为 `[x1, y1, x2, y2]` 的归一化坐标。

## 测试验收

`gst/tests` 应覆盖以下行为：

1. 有效检测字段能通过规范化并进入 store。
2. 轻微越界 bbox 会被 clamp 到 `[0,1]`。
3. `NaN`、无穷值、置信度越界和零面积 bbox 会被丢弃。
4. `class_id` 和 `track_id` 的非法负值会归一为 `-1`。
5. `SsvDetectionStore` 的 `set`、`take_for_tracking`、`set_tracked`、`take`、`peek_latest` 保持现有流转语义。
6. mock 推理输出和真实推理输出进入 `ssv_meta` 前使用同一套字段规范。

建议验证命令：

```bash
./ssv build
meson test -C build
```

## 退出标准

1. 团队能说明 `SsvDetection` 和 `SsvFrameDetections` 每个字段的含义。
2. 团队能说明 bbox 始终是原始视频帧坐标系下的归一化左上右下坐标。
3. 非法检测不会污染 `ssv_meta`、overlay、tracking 和后续发布链路。
4. `gst/tests` 覆盖元数据基本行为和防御规则。
5. 后续 tile、多尺度或安全帽专用模型接入不需要修改 `ssv_meta` 坐标契约。
