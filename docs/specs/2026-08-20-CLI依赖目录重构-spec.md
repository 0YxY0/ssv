# SSV CLI 依赖目录重构 Spec

## 需求

`scripts/ssv_cli/services/dependencies.py` 同时承载 runtime profile 策略、依赖配置校验、外部 SDK 准备、系统工具探针、运行库校验、环境变量管理和依赖快照发布。文件规模和职责跨度使调用方难以判断哪些内容是稳定接口，依赖变更也容易影响构建和运行时的无关逻辑。

本阶段将依赖逻辑整理为独立的 `scripts/ssv_cli/dependencies/` package，并按稳定变化点拆分实现。重构不改变现有依赖行为，只改变模块归属和 import 路径。

## 约束

- `./ssv build --profile auto|cpu|nvidia|intel|amd` 的参数和 profile 解析规则保持不变。
- `.env` 中现有 `SSV_ONNXRUNTIME_*`、`SSV_OPENCV_*`、`SSV_TENSORRT_*`、`CUDA_HOME` 和 `SSV_EXTRA_PKG_CONFIG_PATH` 键保持不变。
- `.deps/onnxruntime*`、`.deps/opencv`、`.deps/tensorrt` 的缓存和安装目录保持不变。
- `build/ssv-deps.env` 的键集合、shell quoting 方式和原子发布语义保持不变。
- 不改变 ONNX Runtime、OpenCV、TensorRT 的版本、下载地址、校验规则或编译选项。
- 不在本阶段重写依赖准备算法，也不把 native SDK 安装改为系统包安装。

## 目标结构

依赖子系统对外提供少量稳定接口，内部按职责组织：

```text
scripts/ssv_cli/
├── commands/
├── dependencies/
│   ├── __init__.py
│   ├── policy.py       # profile、默认值和 DependencyConfig
│   ├── contracts.py    # DependencyResult、DependencySnapshot、快照写入
│   ├── tooling.py      # pkg-config、编译 probe、ELF、下载和文件事务
│   ├── manager.py      # 一次构建的依赖准备编排和签名
│   ├── onnxruntime.py  # ONNX Runtime artifact 和 OpenVINO 路径
│   ├── opencv.py       # OpenCV system/local/managed 路径
│   └── tensorrt.py     # TensorRT、cuDNN 和 CUDA 路径
├── services/
└── tests/
```

外部调用方只依赖 `scripts.ssv_cli.dependencies` 导出的 `DependencyConfig`、`DependencyManager`、`DependencySnapshot`、`load_dependency_manager` 和快照写入接口。三类 SDK 的下载、构建和运行库校验属于依赖 package 的内部实现。

## 非本阶段范围

- 不调整 CLI 命令名称和参数。
- 不改变 `.env` 默认值或 README 中记录的依赖策略。
- 不迁移模型服务、Redis 服务或 GStreamer native 代码。
- 不删除已有行为测试；测试文件只在 import 路径明确改善时同步调整。
