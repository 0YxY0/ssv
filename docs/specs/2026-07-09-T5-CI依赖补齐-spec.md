# T5 CI 依赖补齐 spec

## 背景

PR #15 的 GitHub Actions `Build and Test` 在 `./ssv test` 阶段失败。C++ 编译、Meson 测试、CLI 脚本测试和 Python Agent 测试主体均已运行到后续阶段，但 CI 环境缺少测试脚本实际依赖的工具。

## 问题

- `tests/ssv_cli_test.sh` 使用 `rg` 执行负向匹配检查，CI runner 未安装 `ripgrep`，导致相关检查输出 `rg: command not found`。
- `scripts/lib.sh` 的 `ssv_yaml_get` 使用 `python3` 导入 `yaml` 读取 YAML 配置，CI 的 setup-python 解释器未安装 `PyYAML`，最终抛出 `ModuleNotFoundError: No module named 'yaml'`。

## 目标

- CI 环境显式安装 `ripgrep`，确保 CLI 脚本测试中的 `rg` 检查真实执行。
- CI 环境在 `actions/setup-python` 对应解释器中安装 `PyYAML`，确保 `scripts/lib.sh` 可读取 YAML 配置。
- 不改变 `ssv_meta`、YAML 配置 schema、插件属性、Redis 事件 schema、Agent 输入输出、runner 退出码或日志字段。

## 非本阶段范围

- 不重构 `scripts/lib.sh` 的 YAML 读取实现。
- 不调整 Python Agent 依赖声明。
- 不改变本地链路冒烟测试对 Docker Redis 的依赖与 warning 策略。

## 验收标准

- GitHub Actions 的 `Build and Test` 能安装所有 `./ssv test` 所需 CI 依赖。
- 本地 `bash -n ssv scripts/*.sh tests/*.sh` 通过。
- 本地 `./ssv test` 返回 0；若本地缺少 Docker Redis 能力，链路冒烟测试仍按现有策略降级为 warning。
