# 原始 ONNX 输入契约与预处理 spec

## 背景

当前运行时把 ONNX wrapper 当作唯一可运行模型。`prepare_wrapper.py` 将原始
`float32 [1,3,H,W]` 模型改写为 `uint8 [1,H,W,4]` 的 RGBA wrapper，并把
`Cast -> Gather(RGB) -> Div(255) -> Transpose(NCHW)` 写入 ONNX 图。C++ 侧的
`ssv_model_contract_validate()` 同样强制读取 `ssv.wrapper.*` metadata，
`InferenceBackend::infer()` 只接收 `SsvUint8TensorView`。

这使社区提供的原始 YOLO ONNX 即使具有标准 `float32 [1,3,H,W]` 输入，也会在
启动阶段被拒绝。直接 TensorRT `.engine` 路径还把 wrapper SHA-256、wrapper
contract 和 wrapper metadata 写入 engine manifest，形成同一限制的第二个入口。

现有 runner 会在分析分支生成固定尺寸的 RGBA model canvas：
`SsvAnalysisFramePool` 负责 map 或有界暂存该 canvas，`PreprocessTransform`
负责把模型坐标映射回源画面。第一阶段保留这个 GStreamer 边界，避免同时改动
frame 生命周期、跟踪 GMC 输入和 GPU surface 协商。

## 目标

1. 原始 ONNX 是 ONNX Runtime 路径的唯一模型源文件；运行时不生成、加载或要求
   wrapper ONNX。
2. 启动阶段完成模型 I/O 读取、结构校验、shape/dtype/layout 解析、预处理计划
   创建、host/device buffer 分配、session/engine 创建和 warmup。
3. 第一阶段从既有 RGBA model canvas 一次写入复用的 `float32 NCHW` 输入 buffer，
   不生成 RGBA -> RGB -> float 等中间图像。
4. 模型结构事实从 ONNX 或 TensorRT engine 读取；RGB/BGR、归一化和 resize 语义
   必须由 YAML 显式提供，不从文件名、producer 名称或 ONNX metadata 猜测。
5. ONNX Runtime CPU、CUDA/TensorRT EP 和直接 TensorRT 共用同一 host float tensor
   输入 seam。GPU 预处理以后作为可选 adapter 加入，CPU 预处理始终可用。
6. 直接 TensorRT engine 保留可验证 manifest，但 manifest 不再含 wrapper hash、
   wrapper contract 或 `ssv.wrapper.*` 依赖。
7. 性能数据明确区分已测量、运行时不可归因和未测量，不能把未知路径宣称为零拷贝。

## 本阶段范围

1. 支持一个静态 `float32 [1,3,H,W]`、batch 为 `1` 的原始 ONNX 图像输入。
2. 支持一个或多个静态 `float32` 输出，并继续由现有 `family` 与
   `output_format` 配置选择 YOLO parser。
3. 新增显式预处理配置、启动期模型结构契约、C++ RGBA-to-float-NCHW
   预处理器及其 buffer 生命周期。
4. 统一后端输入、warmup 和运行时计时返回值。
5. 将直接 TensorRT manifest 升级为以原始 ONNX 为来源的 schema v2，并迁移 CLI、
   测试和当前用户文档。
6. 将 analysis canvas 的 resize 语义与 `PreprocessTransform` 绑定，保证
   letterbox 与 stretch 的坐标反变换可验证。

## 非本阶段范围

1. 不在启动时或后台自动生成 wrapper ONNX，也不保留 wrapper 作为兼容回退。
2. 不支持动态 batch、动态空间尺寸、多图像输入、float16/int8 输入、NHWC 原始
   图像输入、分割、姿态或分类模型。
3. 不把 NV12、DMA-BUF、VAMemory、CUDA surface 或 device tensor 直接传入推理
   后端；这些是后续 GPU 预处理 adapter 的工作。
4. 不承诺 host buffer 是 pinned memory，不以“零拷贝”作为优化前提。
5. 不改变 YOLO 输出格式的业务语义、NMS、latest-frame 调度、跟踪或发布协议。
6. 不修改历史 spec/plan 中的历史事实；迁移决策只记录在本文档和对应新 plan。

## 现状差异

| 主题 | 当前实现 | 目标实现 |
| --- | --- | --- |
| ONNX 输入 | wrapper 的 `uint8 [1,H,W,4]` | 原始模型的 `float32 [1,3,H,W]` |
| 输入语义 | 固化在 wrapper 图与 metadata | YAML 的显式预处理配置 |
| 后端入参 | `SsvUint8TensorView` | `SsvFloatTensorView` |
| 模型契约 | `ssv.wrapper.*`、wrapper source hash | 结构化 I/O + 显式配置，无 wrapper metadata |
| 预处理 | ONNX 图内 `Cast/Gather/Div/Transpose` | C++ 单次 RGBA canvas 到 float NCHW 写入 |
| 输入 buffer | 后端仅管理输出，输入借用 frame bytes | `InferenceEngine` 启动时分配并复用 host float buffer |
| TensorRT manifest | `wrapper` 对象、wrapper hash 与 contract | `source_model` 对象、原始 ONNX hash 与 engine I/O 校验 |
| 计时 | `device_us` 混合后端工作，`output_copy_us=0` | 预处理、后端已知阶段和未归因阶段分别表达 |

## 术语

- **结构契约**：从模型或 engine 可靠读取的 tensor 名称、dtype、rank、shape 和 layout。
- **预处理配置**：用户声明的颜色顺序、缩放方式与归一化规则；它不是 ONNX metadata。
- **预处理计划**：启动时由结构契约与预处理配置生成的不可变对象，包含通道映射、
  输出布局、尺寸和归一化参数。
- **model canvas**：runner 分析分支交给 `ssvinfer` 的固定尺寸 RGBA 画面。
- **host tensor seam**：`InferenceEngine` 与全部后端之间借用的 host float tensor 视图。

## 配置契约

当 `inference.enabled=true` 时，`inference.model.preprocess` 必须存在并完整声明：

```yaml
inference:
  model:
    path: models/yolov8n.onnx
    family: yolo
    output_format: yolov8
    label_map: config/model-labels/coco80.txt
    preprocess:
      color_order: rgb
      resize: letterbox
      normalization:
        scale: 0.00392156862745098
        mean: [0.0, 0.0, 0.0]
        std: [1.0, 1.0, 1.0]
  runtime:
    type: onnxruntime
    providers:
      mode: explicit
      order: [cpu]
```

字段语义如下：

| 字段 | 合法值或约束 | 语义 |
| --- | --- | --- |
| `color_order` | `rgb`、`bgr` | 模型三个通道的顺序；RGBA canvas 的 alpha 永远被丢弃。 |
| `resize` | `letterbox`、`stretch` | model canvas 的几何方式；不由模型文件名或输入 shape 推断。 |
| `normalization.scale` | 有限且大于零 | 每个 uint8 像素先乘此值。 |
| `normalization.mean` | 三个有限 float | 按模型通道顺序，在 scale 后相减。 |
| `normalization.std` | 三个有限且大于零的 float | 按模型通道顺序，作为除数。 |

每个输出值的固定计算顺序为：

```text
normalized[c, y, x] = (float(source[channel(c), y, x]) * scale - mean[c]) / std[c]
```

旧 wrapper 的语义用上述配置精确表示为 `rgb`、`letterbox`、
`scale=1/255`、`mean=[0,0,0]`、`std=[1,1,1]`。配置加载必须拒绝缺失字段、未知字段、
非有限值、错误数组长度和非正 `std`；不得以默认颜色顺序或模型文件名静默补全。

## 模型结构契约

`ssv_model_contract_validate()` 不再读取 `ModelMetadata::properties`。第一阶段的
启动校验规则为：

1. 模型恰有一个输入，且至少有一个输出。
2. 输入是 `float32`，rank 为 4，shape 严格为 `[1,3,H,W]`，`H` 与 `W` 均为正的
   静态整数，元素数和字节数不溢出 `size_t`。
3. 输入 layout 是 `NCHW`；layout 由 shape 结构识别后再次校验，不从名称猜测。
4. 输出均为静态 `float32` tensor；现有 parser 继续依据显式 `output_format` 校验其
   所需 shape。
5. `family` 和 `output_format` 仍由配置显式选择，不能从 ONNX 图名称或输出 shape
   推断业务语义。

不满足结构契约时，服务在 scheduler 创建前失败。原始 ONNX 不含任何 custom metadata
是正常情况，不能因此失败。

公开的 `SsvModelContract` 只保留 runner 需要的 geometry：`width`、`height` 和
`resize_mode`。输入 tensor 的名称、dtype、element count 和 host buffer 大小属于
`InferenceEngine` 的内部结构契约；`rgba_u8_nhwc_v1`、`input_bytes`、`contract` 与
`source_sha256` 字段不再是公开 runtime contract。运行时快照需要输入描述时，使用由
结构契约生成的诊断字符串，例如 `float32[1,3,640,640]:NCHW`，而不是 magic wrapper 名称。

## 模块与接口

新的深模块位于 `gst/ssv-infer/model/ssv_image_preprocessor.*`。它的外部接口只暴露：
构建计划、对一个 RGBA canvas 写入调用方提供的 float destination，以及返回该次执行的
计时；它不持有 `GstBuffer`、不创建 session、也不理解 YOLO 输出。

建议的内部接口形状：

```cpp
struct SsvPreprocessPlan {
    TensorSpec input;
    int canvas_width;
    int canvas_height;
    SsvInputColorOrder color_order;
    SsvResizeMode resize_mode;
    float scale;
    std::array<float, 3> mean;
    std::array<float, 3> std;
};

class SsvImagePreprocessor {
public:
    explicit SsvImagePreprocessor(SsvPreprocessPlan plan);

    SsvPreprocessTiming run(
        const SsvRgbaFrameView &canvas,
        std::span<float> destination) const;
};

struct SsvBackendRunResult {
    std::span<const SsvFloatTensorView> outputs;
    SsvBackendRunTimings timings;
};

class InferenceBackend {
public:
    virtual ModelMetadata load(
        const InferenceConfig &, SsvInferenceBufferAllocator &) = 0;
    virtual void warmup(const SsvFloatTensorView &input) = 0;
    virtual SsvBackendRunResult infer(
        const SsvFloatTensorView &input, std::stop_token) = 0;
};
```

`SsvFloatTensorView` 已是输出 host view；迁移后它也成为唯一的第一阶段输入 view。
每个 backend 必须先校验 `spec` 与 host element count，再把 view 交给运行时。该接口不
暴露 ORT/TensorRT device 指针，也不允许 backend 反向读取 RGBA frame。

## 生命周期与所有权

| 资源 | 创建和持有者 | 借用者 | 释放时机 |
| --- | --- | --- | --- |
| `SsvPreprocessPlan` | `InferenceEngine::start()` | `SsvImagePreprocessor`、runner geometry | `InferenceEngine::stop()` |
| host float input buffer | `InferenceEngine` 通过 `SsvInferenceBufferAllocator` | 预处理器写入，backend 在一次 `infer()` 中只读 | engine 停止后 |
| `SsvAnalysisFrame` / RGBA canvas | `SsvAnalysisFramePool` | engine 在 `run()` 期间读取，检测/跟踪按现有共享引用保留 | 最后一个共享引用释放后 |
| ORT session / TensorRT runtime、engine、context | 各 `InferenceBackend` | backend 私有 | backend 析构或 engine 停止 |
| 后端输出 host buffer | 各 backend 通过 allocator | parser 在当前调用中借用 | 下次 `infer()` 或 backend 析构前有效 |
| TensorRT device buffers / stream | `SsvTensorRtExecutionResources` | TensorRT backend 私有 | backend 析构 |

当前 latest-frame scheduler 保证一个 service 同时只执行一个 `InferenceEngine::run()`；因此
一个可复用输入 buffer 足够。这个串行约束是 buffer 安全性的前提，未来若改变 scheduler
并发度，必须改为每个 in-flight request 独占输入 buffer，不能让 span 跨调用复用。

## 启动与逐帧流程

启动流程：

```text
YAML 配置校验
  -> backend 创建 session/engine 并读取 ModelMetadata
  -> 结构契约校验
  -> 构建不可变 SsvPreprocessPlan
  -> 分配可复用 host input 和 backend output/device buffer
  -> backend warmup(input view)
  -> 发布 geometry contract、创建 analysis frame pool、启动 scheduler
```

逐帧流程：

```text
RGBA model canvas
  -> SsvImagePreprocessor 单次通道选择/float/normalize/NCHW 写入
  -> SsvFloatTensorView
  -> InferenceBackend::infer
  -> float output views
  -> YoloOutputParser
  -> 现有 source-coordinate 反变换、跟踪和发布
```

第一阶段的 canvas 已经等于模型 `H x W`，因此预处理器不再次 resize 或 letterbox；这样才
不会发生双缩放，也能逐像素保持旧 wrapper 对既有 canvas 的结果。未来 source RGBA、NV12、
DMA-BUF 或 GPU surface adapter 将复用同一个 `SsvPreprocessPlan`，在 adapter 内把颜色转换、
resize/letterbox、归一化和 layout 以一次写入融合完成。

## 几何与坐标映射

runner 必须根据 `SsvModelContract::resize_mode` 配置 `videoscale` 和 `vapostproc`：

- `letterbox`：要求 `add-borders=true`，并用 letterbox transform。
- `stretch`：要求 `add-borders=false`，并用两个独立缩放系数的 transform。

`PreprocessTransform::scale` 迁移为 `scale_x` 与 `scale_y`；letterbox 时两者相等，
因此现有 source 坐标结果不变。`ssv_unmap_model_detection()` 必须分别使用两轴比例，
并继续扣除实际 padding。所有 canvas caps、transform 和 parser 使用同一计划产物，不能
由三个不同位置各自计算尺寸。

当前 `SsvAnalysisFrame` 的 RGBA view 和映射/暂存生命周期保持不变。以后切换 source-frame
预处理时再改变 pipeline caps；本阶段不以“删除 RGBA canvas”作为优化。

## ONNX Runtime 与 TensorRT

ONNX Runtime `load()` 继续负责 provider 解析、session pool、原始模型 SHA-256、缓存命名空间、
I/O metadata 和输出 buffer。它需要把 tensor type 识别扩展为原始模型所需的 `float32` 输入，
但不能把颜色或归一化写回 metadata。`warmup()` 接收 engine 提供的同一 float input view，
保证 session 编译、EP cache 和 profile warmup 使用真实 tensor contract。

直接 TensorRT backend 继续从 engine 读取 bindings，并复用 `SsvTensorRtExecutionResources`
中的 stream/device buffer。它验证 input spec 与共享 float view 一致后执行 H2D、enqueue、
D2H；不执行 RGBA 转换，不需要 wrapper ONNX。

TensorRT manifest 升级为 schema version 2：

```json
{
  "schema": "ssv.tensorrt-engine-manifest",
  "schema_version": 2,
  "engine": {
    "sha256": "...",
    "precision": "fp16",
    "tensorrt_version": "10.16.1.11",
    "cuda_runtime_version": 13020,
    "compute_capability": {"major": 8, "minor": 9}
  },
  "source_model": {
    "sha256": "...",
    "input": {
      "name": "images",
      "dtype": "float32",
      "layout": "NCHW",
      "shape": [1, 3, 640, 640]
    }
  }
}
```

manifest 只验证 engine 内容、运行时兼容性、原始 ONNX 身份和 engine input I/O 是否一致。
它不承载 `color_order`、归一化、resize、`family` 或 `output_format` 的真相来源；这些仍来自
YAML。schema v1 应以明确的“请从原始 ONNX 重新生成 manifest”错误拒绝，而不是兼容 wrapper
字段。

`write_tensorrt_manifest.py` 的参数从 `--wrapper` 改为 `--model`，读取原始 ONNX 的结构
契约和 SHA-256。`prepare_wrapper.py`、`model prepare` 命令及 wrapper 测试在迁移完成后删除，
防止新用户继续把 wrapper 当作必经步骤。

## 错误语义

| 失败类别 | 发生阶段 | 对外 stage | 行为 |
| --- | --- | --- | --- |
| YAML 预处理字段缺失或非法 | 配置加载 | `inference.model.preprocess.*` | `SsvConfigError`，启动前失败。 |
| 模型输入数量、dtype、shape、layout 不支持 | engine 启动 | `inference.model_contract` | `SsvModelContractError` 经 service 包装，scheduler 不启动。 |
| 模型、manifest、session 或 engine 无法加载 | engine 启动 | `inference.start` | 保留具体后端上下文，启动失败。 |
| v1/损坏/不匹配 TensorRT manifest | engine 启动 | `inference.start` | `SsvTensorRtManifestError`，不尝试 wrapper 回退。 |
| RGBA canvas 与启动计划尺寸不一致 | 单帧 | `inference.run` | 作为失败 submission 处理，并保留 pipeline contract 诊断；不能转换成错误尺寸 tensor。 |
| stop token 已请求 | warmup 之后的单帧 | 现有取消路径 | 取消当前任务，不泄漏借用 view 或 staging lease。 |

任何失败都不得通过“推断颜色顺序”“假定 /255”“改写 ONNX”或“接受 wrapper metadata”来补救。

## 性能与测量

计时字段必须表达数据来源。`0` 只表示已知没有该阶段，例如 ONNX Runtime CPU 没有 H2D/D2H；
不能表示“没有测到”。不可归因值使用 `std::optional` 的空值或日志中的 `unmeasured`。

| 阶段 | 第一阶段的测量来源 | 说明 |
| --- | --- | --- |
| decode | runner/GStreamer pipeline instrumentation | 不由 `InferenceEngine` 伪造。 |
| 颜色转换/resize | analysis pipeline 的 `videoscale`/`videoconvert` 或 `vapostproc` instrumentation | RGBA canvas 阶段归 pipeline 所有。 |
| normalize/layout | `SsvImagePreprocessor::run()` | 计时覆盖单次 C++ RGBA-to-float-NCHW 写入。 |
| H2D / execution / D2H | 直接 TensorRT 使用 CUDA events；ORT EP 无法可靠拆分时标记未归因 | 不把 ORT `Run()` 人为拆成三段。 |
| postprocess | `YoloOutputParser::parse()` 外层 | 与既有 parser 语义分开。 |

融合 CPU loop 不能诚实地在生产热路径中分割“颜色转换”和“normalize/layout”两段。需要更细
粒度比较时，使用同一输入与计划的专用 benchmark，而不是加入中间图像或伪造计时。性能报告必须
列出 CPU 测量、GPU/TensorRT 测量和未测量阶段，不能用理论零拷贝替代实测。

## 验收标准

1. 一个无 `ssv.wrapper.*` metadata 的静态原始 float32 NCHW ONNX 能完成 CPU provider
   启动、warmup 和一次推理。
2. 模型契约测试证明缺少 wrapper metadata 不再失败，并拒绝不支持的 dtype、rank、shape、
   layout 和多输入模型。
3. 预处理单元测试用同一 RGBA canvas 对比旧 wrapper 的 RGB、`/255`、NCHW 数值，覆盖 alpha
   丢弃、RGB/BGR、mean/std 和复用 buffer。
4. letterbox、stretch 和奇数 padding 的坐标反变换测试通过；既有 letterbox 用例的输出不变。
5. 直接 TensorRT manifest 的 v2 测试验证原始模型 hash、engine I/O 比对和 v1 明确拒绝。
6. CPU C++、模型契约、ONNX Runtime backend、pipeline、Python manifest/CLI 测试通过。
7. GPU、TensorRT engine、CUDA event 计时和 GPU surface 预处理单独报告为已验证或未验证，
   不把本地 CPU 结果外推为 GPU 结论。
