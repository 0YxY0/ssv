# T2 安全帽模型验证与接入 spec

## 背景

当前仓库 `models/` 下已有多份新训练的安全帽 `.pt` 模型：

- `models/comp-2-freeze10.pt`
- `models/comp-3-patience30.pt`
- `models/comp-4-coslr-true.pt`
- `models/comp-6-freeze-22.pt`

现有实时推理链路由 `gst/ssv-infer` 提供，插件通过 ONNX Runtime 加载模型。改动前默认配置和脚本指向 `models/yolov8n.onnx`，该模型是 COCO `person` 检测模型，只能验证人员检测链路，不能直接判断安全帽佩戴状态。

改动前 `ssvinfer` 内置 COCO 80 类名称，脚本默认使用 `target-class=person`。安全帽模型即使导出为 ONNX，也需要显式提供模型类别表，否则 `class_id` 只能被解释为 COCO 类别或 `class_N`，下游 `ssvtrack`、`ssvoverlay`、`ssvpub` 无法获得稳定的安全帽类别语义。

本阶段属于 `T2` 感知算法与元数据主线。改动会影响 `ssv_meta` 中的 `class_id`、`class_name` 语义、YAML 配置、`ssvinfer` 插件属性和真实模型 smoke 验证方式；这些接口需要在文档和测试中同步。

## 目标

1. 对 `models/` 下安全帽 `.pt` 模型做离线验证，确认模型可加载、类别表可读取、推理能产生结果摘要。
2. 选定一个安全帽 `.pt` 模型导出 ONNX，作为工程接入候选模型。
3. 扩展 `ssvinfer` 支持可配置 label map，并保持 COCO label map 与脚本默认 `person` 过滤的兼容行为。
4. 让 YAML、脚本和插件属性能把 `model_path`、`target_class`、`label_map`、推理设备和 CUDA 策略传入 `ssvinfer`。
5. 支持 ONNX Runtime CPU/CUDA Execution Provider 选择，默认自动尝试 CUDA 并可回退 CPU。
6. 为安全帽 ONNX 工程接入提供可复现 smoke 命令和测试覆盖。

## 范围

本阶段包含：

1. 新增离线模型验证脚本，用 Ultralytics 直接加载 `.pt` 模型。
2. 新增安全帽模型验证文档，记录模型文件、类别表、导出命令和 smoke 命令。
3. 新增 label map 文件格式和默认 COCO label map 文件。
4. 扩展 `ssvinfer` 插件属性，支持 `label-map`。
5. 扩展 YAML 配置结构，增加 `inference.label_map`。
6. 扩展 `scripts/pipeline.sh`，将 `target_class`、`label_map`、`device`、`cuda-device-id` 和 `cuda-required` 传入 `ssvinfer`。
7. 扩展 ONNX Runtime 依赖脚本，支持 CPU/GPU 运行库 flavor，并隔离 `.deps/onnxruntime` 与 `.deps/onnxruntime-gpu`。
8. 补充 C++ 测试，覆盖 label map、设备属性和旧默认行为。

本阶段不包含：

1. 不评估模型准确率、召回率或生产可用性。
2. 不重新训练模型。
3. 不引入 Python Agent 到每帧同步检测链路。
4. 不把模型下载、ONNX 导出、Docker Redis 启动迁入 C++。
5. 不冻结 Redis 事件 schema，也不实现事件判定。
6. 不承诺所有 `.pt` 都导出成功；工程接入只要求至少一个模型导出 ONNX 并完成 smoke。

## 模型格式约束

`ssvinfer` 的工程运行格式仍为 ONNX：

```text
GStreamer pipeline -> ssvinfer -> ONNX Runtime -> SsvDetectionStore
```

`.pt` 模型只用于离线验证和导出。实时链路不直接加载 `.pt`，避免在 C++ 插件中引入 PyTorch 或 Ultralytics Runtime。

推荐导出命令：

```bash
uv run --with ultralytics python scripts/model/verify_helmet_models.py \
  --models-dir models \
  --source /path/to/validation/images \
  --export models/comp-2-freeze10.pt
```

脚本内部使用 Ultralytics `YOLO(...).export(format="onnx", imgsz=640, simplify=True)` 生成候选 ONNX。导出的 ONNX 文件命名与输入模型同名，例如：

```text
models/comp-2-freeze10.onnx
```

## Label map 契约

新增 label map 文件格式为 UTF-8 文本，每行一个类别名，行号从 0 开始对应模型 `class_id`。安全帽模型示例：

```text
helmet
head
```

空行和以 `#` 开头的行会被忽略。有效类别名保留原始大小写和下划线，不做中文翻译。类别名长度超过 `SsvDetection::class_name` 承载能力时，写入 `class_name` 时按 C 字符串规则截断。

默认 label map 文件：

```text
config/model-labels/coco80.txt
```

安全帽模型 label map 文件：

```text
config/model-labels/helmet.txt
```

`config/model-labels/helmet.txt` 的具体类别顺序必须来自 `.pt` 模型自身的 `model.names`，不得手写猜测。如果多个 `.pt` 模型类别顺序不同，每个模型需要独立 label map 文件。

## 配置契约

YAML 新增字段：

```yaml
inference:
  model_path: "models/yolov8n.onnx"
  confidence_threshold: 0.5
  device: "auto"
  cuda_device_id: 0
  cuda_required: false
  target_class: "person"
  label_map: "config/model-labels/coco80.txt"
```

本节是安全帽模型接入阶段的历史配置设计。当前运行配置已由 `docs/specs/2026-07-07-T2-推理运行时解耦设计-spec.md` 取代：运行参数统一写入 YAML 配置，默认搜索项目根目录 `ssv.yaml`、`config/ssv.yaml` 和 `config/ssv.example.yaml`；脚本不再通过同名环境变量覆盖模型路径、推理设备、类别表、目标类别或 CUDA 策略。仅保留 `SSV_CONFIG_PATH`、`SSV_RTSP_URL`、`GST_DEBUG`、`REDIS_HOST` 和 `REDIS_PORT` 这类配置选择、部署或临时调试变量。

## ssvinfer 行为

`ssvinfer` 新增插件属性：

```text
label-map: Path to model class label map file
device: ONNX Runtime execution device: auto, cpu, or cuda
cuda-device-id: CUDA device id used when CUDAExecutionProvider is enabled
cuda-required: Fail startup when CUDAExecutionProvider cannot be enabled
```

启动行为：

1. `device=cpu` 时只创建 CPU Execution Provider。
2. `device=auto` 或 `device=cuda` 时尝试创建 CUDA Execution Provider，成功后输出 active provider 和 device id。
3. CUDA Execution Provider 不可用且 `cuda-required=false` 时，输出 warning 并回退 CPU Execution Provider。
4. CUDA Execution Provider 不可用且 `cuda-required=true` 时，插件启动失败。
5. `label-map` 为空时，使用内置 COCO 80 类，保持现有兼容行为。
6. `label-map` 非空时，从文件加载类别名。
7. 如果 `label-map` 文件不存在或没有有效类别，插件启动失败并输出明确错误。
8. 如果 ONNX 输出类别数与 label map 有效类别数不一致，插件启动失败并输出模型类别数和 label map 类别数。
9. `target-class` 为空字符串时不过滤类别。
10. `target-class` 非空但不在当前 label map 中时，插件启动失败，避免静默输出空检测。
11. `class_id` 使用模型输出类别索引，`class_name` 使用当前 label map 中的类别名。

`ssvinfer` 需要支持两类 ONNX 输出：

1. YOLOv8 原始输出 `(1, 4 + classes, anchors)`，继续执行类别分数过滤、letterbox 反算和 NMS。
2. Ultralytics 导出的 Nx6 输出 `(1, detections, 6)`，按 `[x1, y1, x2, y2, score, class_id]` 解析，执行类别过滤和 letterbox 反算。

`ssv_meta` 归一化坐标契约保持不变。

## 离线验证输出

离线验证脚本输出 JSON 摘要，默认路径：

```text
artifacts/model-verification/helmet-model-summary.json
```

摘要至少包含：

```json
{
  "models": [
    {
      "path": "models/comp-2-freeze10.pt",
      "names": {"0": "helmet", "1": "head"},
      "load_ok": true,
      "predict_ok": true,
      "exported_onnx": "models/comp-2-freeze10.onnx"
    }
  ]
}
```

如果运行环境缺少 Ultralytics、测试图片或导出依赖，脚本必须失败并输出明确错误。最终交付说明中记录未执行项和原因。

## 测试验收

必须覆盖：

1. `ssvinfer` 无 `label-map` 时仍使用 COCO 默认标签，`person` 映射为 `class_id=0`。
2. `ssvinfer` 使用自定义 label map 时，`target-class` 按自定义类别表解析。
3. label map 文件不存在、为空、类别数不匹配、`target-class` 不存在时有明确失败。
4. `ssv_config` 能读取 `inference.label_map`、`inference.device`、`inference.device_id`、`inference.runtime`、`inference.precision`、`inference.model_family` 和 `inference.output_format`。
5. `scripts/pipeline.sh` 能从 YAML 配置读取 `target_class`、`label_map`、`device`、`device_id`、`runtime`、`precision`、`model_family` 和 `output_format` 并传入 `ssvinfer`。
6. `ssvinfer` 暴露 `device`、`device-id`、`runtime`、`precision`、`model-family`、`output-format` 属性，并默认使用通用配置字段。

建议验证命令：

```bash
./ssv build
meson test -C build
bash tests/ssv_cli_test.sh
```

离线模型验证命令：

```bash
uv run --with ultralytics python scripts/model/verify_helmet_models.py --models-dir models --source /path/to/validation/images
```

工程 smoke 命令：

```bash
./ssv run
```

## 退出标准

1. 团队能说明当前 `.pt` 模型不能被 `ssvinfer` 直接加载，工程链路接入格式是 ONNX。
2. 至少一个安全帽 `.pt` 模型完成离线加载、类别表读取和 ONNX 导出。
3. `ssvinfer` 支持安全帽 label map，并保持 COCO label map 与脚本默认 `person` 过滤的兼容行为。
4. 安全帽 ONNX smoke 命令和失败条件记录清楚。
5. 相关测试通过；无法运行的验证在最终说明中写明环境原因。
6. 运行日志能说明 ONNX Runtime 请求设备和最终 active provider，避免误把 GPU 解码当作 GPU 推理。
