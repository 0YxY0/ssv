# 软件解码 NV12 协商修复规范

## 1. 背景

当 VAAPI/NVDEC 不可用时，`auto` 解码模式回退到 `avdec_h264` 软件解码。软件解码器
常见输出 `I420`，而 pipeline 在 `decode-memory-caps` 处把解码输出硬约束为
`video/x-raw,format=NV12`，中间没有格式转换元素，导致 `not-negotiated` 和
`Internal data stream error`。

## 2. 目标

软件解码路径在 `h264-decoder` 与 `decode-memory-caps` 之间插入 `videoconvert`，把解码器
实际输出转换为共享的 NV12 契约，使 `--display --overlay` 在没有硬件解码器的主机上
也能进入 PLAYING 并运行。

## 3. 设计

- 在 `pipeline_internal::resolve_topology` 中，仅当 `SsvDecodeBackend::Software` 时
  向 `topology.prefix` 插入 `stage("videoconvert", "decode-format")`。
- VAAPI/NVDEC 路径不变：VAAPI 仍要求 `VAMemory+NV12`，NVDEC 输出本身是 NV12。
- `decode-memory-caps`、`decode-clock`、`decoded-tee` 顺序与现有契约保持不变。

## 4. 验收

1. `test_ssv_pipeline_builder` 断言软件路径包含 `decode-format`，硬件路径不包含。
2. 本机 `./ssv run --display --overlay` 不再出现 `not-negotiated`，
   模型与 Redis 就绪后可进入 PLAYING。
3. `./ssv test` 的 Meson 测试全部通过。

## 5. 验证结果（2026-08-07）

- pipeline builder 测试通过；`./ssv test` 的 Meson 30/30 通过。
- 本机 `./ssv run --display --overlay` 以 `avdec_h264` + `gtksink` 进入 PLAYING，
  约 15fps 无丢帧，不再出现 `not-negotiated`。
