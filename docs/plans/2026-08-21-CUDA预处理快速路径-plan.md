# CUDA 预处理快速路径计划

本计划实施 [CUDA 预处理快速路径 spec](../specs/2026-08-21-CUDA预处理快速路径-spec.md)。
现有工作树中的 raw ONNX 输入契约、CPU fallback 和阶段计时改动属于前置工作，必须保留，
不重置、不覆盖、不提交。

## 实施约束

- 每个步骤开始编辑前报告精确文件、标识符、接口和所有权影响；
- 每步完成后保持本步骤改动未暂存，先运行针对性验证；
- 不提交、不推送、不创建 PR；
- 不把真实 GPU/TensorRT 未运行写成已验证；
- 不引入 CUDA 作为 CPU/无 TensorRT 构建的强制依赖。

## 步骤 1：配置与预处理计划

文件：

- `gst/ssv-common/include/ssv_config.hpp`：新增 `SsvPreprocessExecution` 和
  `SsvPreprocessConfig::execution`；
- `gst/ssv-common/config/ssv_config.cpp`：解析 `execution`，拒绝未知值；
- `gst/ssv-common/tests/test_ssv_config.cpp`：覆盖默认值、合法值、未知值和错误类型；
- `gst/ssv-infer/model/ssv_image_preprocessor.hpp/.cpp`：把 execution 固化到
  `SsvPreprocessPlan`；
- `config/ssv.example.yaml`：加入 `execution: auto` 示例；

验证：`ssv-config`、`ssv-image-preprocessor`。

## 步骤 2：backend hardware preprocess seam

文件：

- `gst/ssv-infer/core/ssv_inference_backend.hpp`：新增
  `SsvHardwarePreprocessInput`、能力查询和默认 hardware execute adapter；
- `gst/ssv-infer/core/ssv_inference_engine.hpp/.cpp`：根据 plan 和 backend 能力选择
  CPU 或 hardware seam；将 `preprocess_us` 映射到 normalize/layout；显式 cuda 不可用时
  在启动失败；
- `gst/ssv-infer/tests/test_ssv_inference_service.cpp`：验证 CPU、auto fallback、显式
  cuda failure 和 borrowed frame lifetime；
- `gst/ssv-infer/tests/support/ssv_inference_test_service.cpp`：如需适配 fake backend
  的默认结果字段，只做局部初始化修正；

验证：`ssv-inference-service`、`ssv-provider-runtime`。

## 步骤 3：TensorRT resources 与 CUDA kernel

文件：

- `gst/ssv-infer/backends/tensorrt/ssv_tensorrt_resources.hpp/.cpp`：扩展 CUDA API、
  可复用 RGBA scratch、硬件预处理调用和 preprocess CUDA event；
- `gst/ssv-infer/backends/tensorrt/ssv_tensorrt_cuda_kernel.hpp`：声明可选 kernel
  launcher；
- `gst/ssv-infer/backends/tensorrt/ssv_tensorrt_cuda_kernel.cu`：实现 RGBA-to-float-NCHW
  融合 kernel；
- `gst/ssv-infer/backends/tensorrt/ssv_tensorrt_backend.cpp`：实际 CUDA runtime adapter、
  TensorRT hardware execute、能力查询和 timing；
- `gst/ssv-infer/backends/tensorrt/ssv_tensorrt_backend_stub.cpp`：保持无 SDK 构建时
  明确不支持硬件预处理；
- `meson.build`、`gst/ssv-infer/meson.build`：仅在 TensorRT 可用且 CUDA compiler 可用
  时加入 `.cu`，CPU/无 CUDA 构建仍可编译；
- `gst/ssv-infer/tests/test_ssv_tensorrt_resources.cpp`：fake CUDA API 覆盖 scratch
  复用、kernel launch 顺序、释放顺序和计时段；

验证：`ssv-tensorrt-resources`、`ssv-tensorrt-cuda-kernel`、编译 TensorRT backend。fake
adapter 资源测试和 RTX 4060 上的 kernel 数值测试已通过；真实 TensorRT engine smoke 使用
仓库现有 `yolo26n.raw.engine` 时因 engine 与当前 TensorRT 10.16.1.11 不匹配而无法反序列化，
端到端 engine 数值和 CUDA event 计时保留为待匹配软件栈验证项。

## 步骤 4：文档与验收

文件：

- `README.md`：说明 `execution` 选择、TensorRT-only 现状和 GPU 未验证范围；
- `docs/安全帽模型验证说明.md`：更新硬件路径与 CPU fallback 说明；
- `gst/ssv-infer/tests/meson.build`：注册新增测试（若新增独立测试）；

验证顺序：

1. `meson compile -C build`；
2. `meson test -C build --print-errorlogs`；
3. Python CLI/manifest 测试；
4. `git diff --check`；
5. 检查 `git status`，确认前置 staged 内容未被重新暂存，新增步骤保持未暂存。

最终报告明确区分 CPU/fake adapter 验证、真实 CUDA kernel 数值验证，以及尚未完成的匹配
TensorRT engine 端到端验证和真实 CUDA event 计时验证。
