# T5 本地依赖管理收敛 plan

**日期：** 2026-07-20
**主线：** T5 工程集成与质量
**跨主线影响：** T1 实时视频链路与运行时、T2 感知算法与元数据
**设计依据：** `docs/specs/2026-07-20-T5-本地依赖管理收敛-spec.md`
**状态：** 已实施并通过本地验证

## 1. 实施原则

1. 先建立脚本测试和统一接口，再迁移三个 provider，最后删除旧实现。
2. 每一步保持 ONNX Runtime CPU 默认路径可构建，TensorRT 无 SDK 时始终保留明确 stub。
3. 不保留旧变量、旧 Meson option 或兼容分支。
4. managed SDK 的替换必须在临时目录验证完成后原子发布。
5. Meson 只消费 pkg-config；所有 SDK 发现和准备逻辑留在 Bash。
6. 本机不运行 ONNX Runtime GPU；TensorRT 使用与目标 engine 匹配的 `11.1.0.106` SDK 完成真实 C++ 验收。
7. 现有未提交改动属于其他工作，实施时不得回退或覆盖。

## 6. 任务 4：迁移 OpenCV managed provider 并补充 local provider

11. 实现统一三行 stdout 协议。

15. include 支持 `include` 或 `include/opencv4`，路径支持普通空格并写入依赖签名与快照。
16. 拒绝缺失模块、损坏 ELF、未解析符号、头文件/运行库版本不一致及非 `4.10.0` SDK。

验收重点：

## 14. 风险控制

### OpenCV 二进制 ABI 不兼容

通过 readelf 和最小运行探针在原子替换前发现；失败时保留旧 ROOT，并提示使用 system 来源。

### 混合 source 命中错误 pc

在 Meson 前用 `pkg-config --variable=pcfiledir` 核对真实来源；system 依赖被 managed 路径遮蔽时立即失败。

### 构建失败污染运行环境

使用 pending env；只有配置和编译成功才发布成功快照。

### 下载中断或缓存损坏

使用同目录临时下载和原子改名；确认坏缓存后自动删除并重下最多一次。

### 自定义 ROOT 覆盖无关数据

拒绝宽泛路径；非空且无法识别为相同 SDK 时不替换。

### TensorRT 归档体积和版本匹配

官方 SDK 归档体积较大，使用 `.deps/downloads/tensorrt` 缓存避免重复下载。版本按目标 engine 的构建 runtime 精确选择 `11.1.0.106`，不使用目录中较旧的 `11.0.0.114` 替代；真实验收后仍保留 stub/disabled 回归。

## 15. 完成判定

实施完成必须同时满足：

1. spec 的全部退出标准成立。
2. 默认 managed 构建、Meson 测试、CLI 测试、依赖脚本测试和 Agent 测试通过。
3. OpenCV disabled 和 TensorRT stub 路径通过。
4. TensorRT `11.1.0.106` 真实 SDK 构建和目标 engine 验证通过，且没有 ONNX GPU 下载行为。
5. README、`.env.example` 和 CI 与新契约一致。
6. 最终说明明确列出未执行的 ONNX Runtime GPU 验证及原因。
