# T2 推理运行时解耦设计 plan

## 目标

基于 `docs/specs/2026-07-07-T2-推理运行时解耦设计-spec.md`，将 `gst/ssv-infer` 从单一 ONNX Runtime 插件实现重构为分层推理架构。最终结构中，GStreamer 插件只负责视频链路适配，ONNX Runtime 和 TensorRT 都通过统一 `InferenceBackend` 接口接入。

## 实施原则

1. 先补类型和测试，再迁移真实后端。
2. 每一步保持 `mock-detect` 可用，避免无模型环境失去基础测试能力。
3. 不保留旧 YAML 字段兼容；配置样例和测试一次性切到通用字段。
4. TensorRT 按可选构建能力推进，不阻塞默认开发环境。
5. 不把 `.onnx` 到 `.engine` 的构建放入 C++ 插件。
6. 不引入跨插件 tensor 协议，预处理只拆成 C++ 类。

## 任务 7：接入 TensorRT 可选后端

改动文件：

- 新增 `gst/ssv-infer/ssv_tensorrt_backend.hpp`
- 新增 `gst/ssv-infer/ssv_tensorrt_backend.cpp`
- 新增 `gst/ssv-infer/ssv_tensorrt_backend_stub.cpp`
- 修改 `gst/ssv-infer/meson.build`
- 修改 `meson.options`

步骤：

1. 新增 Meson 选项 `tensorrt=auto|enabled|disabled`。
2. 在 `auto` 模式检测 TensorRT headers 和 libraries。
3. 未检测到 TensorRT 时编译 stub。
4. `enabled` 模式未检测到 TensorRT 时配置失败。
5. `SSV_TENSORRT=enabled ./ssv build` 使用 `SSV_TENSORRT_ROOT`、`SSV_TENSORRT_ARCHIVE` 或使用者显式设置的 `SSV_TENSORRT_URL` 提供 TensorRT SDK，并生成本地 `nvinfer.pc`，不依赖系统 TensorRT 安装或特定包管理器，也不自动选择 TensorRT 默认版本。
6. 实现 TensorRT 后端加载 `.engine`、创建 runtime/engine/context、分配 buffer 和 enqueue。
7. 输入输出边界保持 CPU host tensor。
8. `device=cpu` 明确失败，`device=auto` 等价 `gpu`。

默认环境验收：

```bash

meson test -C build
```

TensorRT 环境验收：


## 回滚策略

1. 每个任务独立提交，接口类型、ONNX 后端迁移和 TensorRT 接入分开提交。
2. 如果 TensorRT 接入阻塞，保留 `InferenceBackend`、`OnnxRuntimeBackend` 和 TensorRT stub，后续单独补真实后端。
3. 如果配置改造影响脚本运行，优先修复脚本和 YAML，不恢复旧 `cuda-*` 字段。
4. 如果真实模型 smoke 因本地模型或视频源缺失无法执行，在最终说明中记录环境原因，不能跳过自动测试。
