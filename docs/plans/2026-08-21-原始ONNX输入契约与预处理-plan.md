# 原始 ONNX 输入契约与预处理计划

## 依据与边界

本计划实施 `docs/specs/2026-08-21-原始ONNX输入契约与预处理-spec.md`。目标是让原始
YOLO ONNX 直接进入视频推理链路，而不是仅删除 `prepare_wrapper.py` 后留下 `uint8 RGBA`
后端接口。

每一步完成后保持该步变更为未暂存状态，供人工审阅。收到开始下一步的明确指示后，先检查
`git diff` 与 `git status`，再只暂存上一已验证步骤及必要文档；本计划不包含提交、推送或
创建 PR。

步骤之间必须保持可编译、可验证。步骤 1 只引入并校验显式预处理配置，暂不切换现有
`uint8` 运行时 seam；步骤 2 作为一个垂直切片同时切换公开模型契约、原始 `float32` 输入
校验、预处理器、engine 和全部后端的 float seam。这样不会在后端仍接收
`SsvUint8TensorView` 时留下半迁移的 `SsvModelContract`。

涉及标识符：

- 新增 `SsvInputColorOrder`、`SsvResizeMode`、`SsvNormalizationConfig`、
  `SsvPreprocessConfig`、`SsvModelConfig::preprocess`。
- 扩展 `InferenceConfig`，使其携带已解析的预处理语义。
- 保留现有 `SsvModelContract` 和 `ssv_model_contract_validate()`，避免在旧输入 seam
  仍运行时提前删除其字段；步骤 2 再一次性切换到内部结构契约。

接口与所有权：

- YAML loader 是预处理语义的唯一配置所有者；模型 metadata 只拥有结构事实。
- engine 将拥有内部 `SsvModelInputContract`，runner 只读取公开 canvas geometry。

实施与验证：

2. 覆盖 `preprocess` 缺失、未知字段、错误数组长度、非有限值、非法颜色顺序/resize
   和非正 scale/std；验证合法 RGB/letterbox 与 BGR/stretch 配置的解析结果。
3. 运行 `meson test -C build ssv-config`，
   再运行 `git diff --check`。

涉及标识符：

- 新增 `SsvPreprocessPlan`、`SsvPreprocessTiming`、`SsvImagePreprocessor::run()`。
- `InferenceEngine::start()`：创建 plan 并通过 `SsvInferenceBufferAllocator` 分配一次
  `input_buffer_`。
- `InferenceEngine::run()`：以 `SsvAnalysisFrame::view()` 写入复用 buffer，再形成
  `SsvFloatTensorView`。
- `InferenceBackend::warmup()` 与 `InferenceBackend::infer()`：统一接收
  `SsvFloatTensorView`；ORT、TensorRT 和 stub 在本步骤同时迁移。
- `SsvModelContract`：删除 `input_bytes`、`contract`、`source_sha256`，保留公开 geometry
  和 resize mode；新增内部 `SsvModelInputContract`，让
  `ssv_model_contract_validate()` 只验证原始 `float32 [1,3,H,W]` 结构。

- `InferenceEngine` 拥有 `input_buffer_` 与预处理器；预处理器只借用 destination span，
  不保存 RGBA 指针。
- `SsvAnalysisFrame`、staging lease、`SsvRgbaFrameView` 不迁移；它们在 `run()` 内保持
  既有所有权和释放规则。
- 单次 `run()` 返回前，backend 已消费输入 span；不允许 span 跨 scheduler 任务保存。

实施与验证：

1. 实现单次遍历的 alpha 丢弃、RGB/BGR 选择、float 转换、scale/mean/std 与 NCHW 写入。
2. model canvas 尺寸或 destination element count 不匹配时失败，绝不截断或重分配。
3. 用独立 reference 计算比较旧 wrapper 的 RGB `/255` NCHW 语义，覆盖 RGB/BGR、alpha、
   mean/std、异常输入及相同 buffer 地址复用。
4. 扩展 service 测试，确认正常完成、取消、失败和检测共享 frame 时不泄漏 staging lease。
5. ORT I/O 读取接受 float32 输入，仍拒绝不支持的 tensor type 与动态 shape；CPU fixture
   使用无 metadata 的 raw float NCHW ONNX 完成 start、warmup、提交一帧和输出 buffer 验证。
6. TensorRT backend/stub 与 provider fixture 使用同一 float input seam，验证可用 SDK 下的
   float H2D size、输出回传和取消路径；无 SDK 环境继续验证 stub。
7. 运行新增预处理测试、`ssv-inference-service`、`ssv-provider-runtime`、
   `ssv-tensorrt-unavailable`、可用时的 `ssv-tensorrt-resources`、`ssv-analysis-frame` 和
   `git diff --check`。
