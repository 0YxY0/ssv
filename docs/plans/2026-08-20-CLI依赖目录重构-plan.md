# SSV CLI 依赖目录重构 Plan

## 步骤 1：固定依赖 package 的接口

新增中文 spec 和本 plan，确认本次只做目录和模块职责重组，不改变依赖策略、缓存路径、快照格式和构建行为。

## 步骤 2：拆分依赖实现

将 `services/dependencies.py` 迁移到 `dependencies/` package，并拆分为：

- `policy.py`：profile 检测、Provider 契约、`.env` 组合校验和 `DependencyConfig`。
- `contracts.py`：依赖结果、依赖快照和原子快照写入。
- `tooling.py`：外部命令、pkg-config、编译/加载 probe、ELF/ldd、下载解包和原子目录操作。
- `onnxruntime.py`：CPU/NVIDIA artifact、Intel OpenVINO 源码构建以及 ONNX Runtime 校验。
- `opencv.py`：system/local/managed OpenCV 准备和校验。
- `tensorrt.py`：managed/system TensorRT、cuDNN、CUDA 检测和校验。
- `manager.py`：依赖准备顺序、运行库路径、依赖签名、摘要和快照发布。

内部模块通过一个构建 workspace 共享命令环境和 pkg-config/runtime 路径；外部仍通过 `DependencyManager.prepare()` 使用整个依赖子系统。
本步骤暂时保留 `services/dependencies.py` 的兼容 re-export，待下一步骤完成调用方迁移后删除。

## 步骤 3：收口调用方

更新 `native_build.py`、`runtime_env.py`、CLI 测试和相关文档引用，删除 `services/dependencies.py` 旧入口，确保调用方不再依赖依赖模块的内部常量和实现文件。

## 步骤 4：验证

运行 Python CLI 单元测试、必要的格式和静态检查，另外执行 `./ssv build --help` 验证入口未受影响。若宿主缺少完整 native SDK，不执行真实依赖下载或编译，并记录剩余风险。

## 提交边界

每个步骤完成后保持变更未暂存，供人工审阅；未经明确指示不提交、不推送、不创建 PR。
