# T1/T2 运行时与模块结构收口实施计划

## 实施顺序

本计划已完成，按“契约 → owning runtime → runner → 目录 seam → 依赖快照 → 观测验证”的顺序
组织：

1. 固定 YAML v2、错误码、pipeline plan 和公开 inference service；
2. 建立 Provider/runtime snapshot、session/cache 所有权和 fallback 事件；
3. 抽取 SsvLatestFrameScheduler，保持 latest-pending 行为；
4. 将 runner 拆为 pipeline、runtime、display 和 observability；
5. 将 inference、track、common 的 implementation 迁移到 core/adapter/plugin/public 局部；
6. 收口依赖脚本、模型准备、Meson options 和运行库快照；
7. 补齐 logger、CLI、契约测试和 CI 环境验证。

## 实施落点

### 1. Inference runtime and scheduler

- gst/ssv-infer/public/
- gst/ssv-infer/core/
- gst/ssv-infer/model/
- gst/ssv-infer/backends/
- gst/ssv-infer/plugin/
- gst/ssv-infer/tests/

SsvInferenceService 保留模型执行、analysis frame pool 和 source geometry 的所有权；
SsvLatestFrameScheduler 只拥有任务状态、worker、pending replacement、cancel/stop 和 stats
window，通过注入执行函数调用 engine。

### 2. Runner runtime and observability

- runner/pipeline/
- runner/runtime/
- runner/display/
- runner/observability/
- runner/main.cpp

SsvPipelinePlan 不执行资源创建；SsvPipelineBuilder 不解析配置；SsvRunAttempt 管理一次尝试
的资源释放和停止顺序；SsvEventLog 将 runtime domain event 转为稳定输出。

### 3. Track/common locality

- gst/ssv-common/config|frame|meta|tests
- gst/ssv-track/core|adapters|plugin|tests

算法 core 不依赖 GStreamer 或 SSV metadata。adapter 负责检测转换、坐标变换、GMC frame 和
geometry reset；plugin 只保留生命周期、metadata consume/publish 和错误映射。

### 4. Dependency and model workflow

- scripts/deps.sh
- scripts/deps/common.sh
- scripts/deps/onnxruntime-profile.sh
- scripts/deps/onnxruntime-managed.sh
- scripts/deps/tensorrt-managed.sh
- scripts/build.sh
- scripts/run.sh
- scripts/prepare-model.sh
- scripts/model/prepare_wrapper.py
- scripts/model/write_tensorrt_manifest.py
- meson.build、meson.options、.env.example

所有 build/run/inspect 入口读取同一成功 dependency snapshot。模型准备只生成受保护的 wrapper/
manifest，不在运行时隐式转换模型。

### 5. Documentation and CI

- README.md、CONTEXT.md、AGENTS.md
- .github/workflows/ci.yml
- tests/ssv_cli_test.sh
- tests/ssv_deps_test.sh
- tests/ssv_prepare_model_test.py
- tests/ssv_tensorrt_manifest_test.py

文档只保留本计划与配套 detection display 计划作为本次交付的主题记录。CI 安装 libgtk-3-dev
以匹配 runner display 的 gtk+-3.0 build dependency。

## 验证

    bash -n ssv scripts/*.sh scripts/deps/*.sh tests/*.sh
    bash tests/ssv_deps_test.sh
    bash tests/ssv_cli_test.sh
    meson compile -C build
    meson test -C build --print-errorlogs

验证应覆盖：

- provider/profile/ABI 和 dependency snapshot round-trip；
- runtime fallback、attempt lifecycle 和 structured event；
- scheduler 的 replacement、cancel、stop、failure recovery；
- public inference interface、track adapter 和目录 include seam；
- 无配置时 CLI 不误启动 smoke，有配置时 smoke 有界退出；
- CI 在 Ubuntu runner 上能找到 GTK、GStreamer、yaml-cpp、hiredis、BLAS/LAPACK 和模型工具。
