# 安全帽模型验证说明

本文说明如何验证外部 Ultralytics/PyTorch 安全帽权重，并将导出的原始 ONNX 接入当前 SSV 推理链路。`.pt` 只用于离线验证和导出，正式 runner 不直接加载 PyTorch 权重。

## 当前边界

当前正式推理路径接受：

- 原始 ONNX：唯一输入为静态 `float32 [1,3,H,W]`、NCHW，输出为静态 float32 tensor。
- TensorRT engine：由同一个原始 ONNX 在目标机器上构建，并配套 schema v2 manifest。

运行时不要求 `ssv.wrapper.*` metadata，也不生成 wrapper ONNX。颜色顺序、resize/letterbox、归一化和执行位置由 YAML 的 `inference.model.preprocess` 显式配置。

仓库提供安全帽类别表：

```text
config/model-labels/helmet.txt
0: helmet
1: head
```

类别表只是 `class_id` 映射，不代表仓库包含安全帽权重，也不代表已经完成精度评估。

## 验证外部 `.pt` 权重

根项目需要 Ultralytics 时同步导出 extra：

```bash
uv sync --extra dev --extra model-export
```

把外部权重放到单独目录，并保持文件名匹配 `comp-*.pt`。仅检查模型能否加载、类别表和可选图片/视频推理：

```bash
./ssv model verify \
  --models-dir /path/to/helmet-models \
  --source /path/to/validation/images \
  --output artifacts/model-verification/helmet-model-summary.json
```

`--source` 可以省略，此时只加载模型并记录 `names`；传入后脚本会执行 Ultralytics `predict`，把类别和 confidence 写入 JSON。该摘要是离线验证结果，不是 SSV pipeline 的端到端结果，也不等同于 precision、recall 或 mAP 报告。

如果目录中没有匹配的 `comp-*.pt`，命令会报告 `No comp-*.pt models found`；这表示验证输入缺失，不表示 ONNX runtime 推理失败。

## 导出并检查原始 ONNX

验证时可以同时导出某个权重：

```bash
./ssv model verify \
  --models-dir /path/to/helmet-models \
  --source /path/to/validation/images \
  --export /path/to/helmet-models/comp-2-freeze10.pt
```

脚本调用 `model.export(format="onnx", imgsz=640, simplify=True)`，实际生成路径和类别顺序以 Ultralytics 输出及摘要中的 `names` 为准。导出后应使用 ONNX 检查工具确认：

```text
唯一输入：float32 [1,3,H,W]，NCHW，静态 shape
输出：静态 float32 tensor
```

如果模型输入不是上述契约，当前 SSV runtime 会在启动阶段拒绝它。不要把 `.pt` 路径直接写入 `inference.model.path`。

## 配置 SSV

安全帽模型通常使用自定义 label map。下面的配置假定导出的原始 ONNX 输出适合 `yolov8`；如果输出已经是 `[1,N,6]` 的 `[x1,y1,x2,y2,score,class_id]`，改用 `yolo_nx6`：

```yaml
inference:
  enabled: true
  analysis_fps: 15
  model:
    path: "models/comp-2-freeze10.onnx"
    family: "yolo"
    output_format: "yolov8"
    label_map: "config/model-labels/helmet.txt"
    preprocess:
      color_order: "rgb"
      resize: "letterbox"
      execution: "auto"
      normalization:
        scale: 0.00392156862745098
        mean: [0.0, 0.0, 0.0]
        std: [1.0, 1.0, 1.0]
  runtime:
    type: "onnxruntime"
    providers:
      mode: "auto"
    device_id: 0
    precision: "auto"
  confidence_threshold: 0.5
  target_class: "helmet"
```

配置要点：

- `label_map` 的行号必须和模型的 `class_id` 一致；当前 `helmet.txt` 是 `helmet`、`head` 两类。
- `target_class: "helmet"` 只保留类别 0；设为空字符串可观察全部类别。
- `target_class` 必须精确匹配 label map 中的名称。
- `color_order`、`resize` 和 `normalization` 必须按模型训练/导出语义填写，运行时不会根据文件名或 ONNX metadata 猜测。
- `execution: auto` 在可用的直接 TensorRT CUDA adapter 上使用硬件预处理，否则使用 CPU；`cpu` 强制 CPU，`cuda` 在能力不足时启动失败。

## 构建和 smoke

```bash
./ssv build --profile cpu
./ssv inspect
./ssv run --headless
```

使用 NVIDIA、Intel 或 AMD profile 时，先按 [依赖与构建](依赖与构建.md) 准备对应 provider。模型和配置验证可用：

```bash
./ssv test
```

本地 CPU 测试可以验证原始 float32 NCHW ONNX 的启动、warmup、预处理和单帧推理；GPU Provider、真实 TensorRT engine、CUDA event 和 GPU surface 预处理必须在对应硬件上单独验收。

## TensorRT 对照路径

TensorRT backend 只加载已经构建好的 engine，不在 runner 内把 ONNX 转成 engine。应在最终运行机器上从同一个原始 ONNX 构建：

```bash
trtexec \
  --onnx=models/comp-2-freeze10.onnx \
  --saveEngine=models/comp-2-freeze10.engine \
  --fp16

./ssv model manifest \
  --model models/comp-2-freeze10.onnx \
  --engine models/comp-2-freeze10.engine \
  --output models/comp-2-freeze10.engine.json \
  --precision fp16 \
  --tensorrt-version 10.16.1.11 \
  --cuda-runtime-version 13020 \
  --compute-capability 8.9
```

示例中的 TensorRT、CUDA 和 compute capability 必须替换为构建并运行 engine 的实际值。manifest schema v2 记录 engine hash、原始 ONNX hash、engine 版本/设备信息和输入 I/O，不记录 wrapper metadata。

对应的 engine 配置为：

```yaml
inference:
  model:
    path: "models/comp-2-freeze10.engine"
    manifest: "models/comp-2-freeze10.engine.json"
    family: "yolo"
    output_format: "yolov8"
    label_map: "config/model-labels/helmet.txt"
  runtime:
    type: "tensorrt-engine"
    device_id: 0
```

## 失败定位

| 现象 | 优先检查 |
| --- | --- |
| `No comp-*.pt models found` | `--models-dir` 是否指向外部权重目录，文件名是否匹配 `comp-*.pt` |
| `ultralytics` 缺失 | 执行 `uv sync --extra dev --extra model-export` |
| `raw model input must be static float32 [1,3,H,W]` | ONNX 是否唯一输入、float32、静态 NCHW |
| `raw model outputs must use float32` | 输出 dtype 是否为 float32 |
| `label-map class count mismatch` | 模型类别数与 `helmet.txt` 行数是否一致 |
| `target-class not found in label-map` | `target_class` 是否精确写成 `helmet` 或 `head` |
| 有检测但类别不对 | 检查导出模型的 `names` 顺序和 label map 行顺序 |
| TensorRT manifest 不匹配 | 是否使用同一个原始 ONNX、engine、TensorRT/CUDA/GPU 重新生成 manifest |
