# 安全帽模型验证说明

## 模型文件

本阶段验证 `models/comp-*.pt`。这些文件是 Ultralytics/PyTorch 权重，不能被 `ssvinfer` 直接加载。

现有工程实时链路通过 `ssvinfer` 和 ONNX Runtime 加载 ONNX 模型。安全帽 `.pt` 需要先完成离线验证，再导出 ONNX 后接入工程 smoke。

## 离线验证

只验证模型能加载并读取类别表：

```bash
uv run --with ultralytics python scripts/model/verify_helmet_models.py --models-dir models
```

带图片或视频源验证：

```bash
uv run --with ultralytics python scripts/model/verify_helmet_models.py --models-dir models --source /path/to/validation/images
```

输出摘要默认写入：

```text
artifacts/model-verification/helmet-model-summary.json
```

## 实施结果总结

本次 T2 安全帽模型验证与接入计划已完成工程落地。原实时链路确认仍以 ONNX Runtime 加载 ONNX 模型，`models/` 下的 `.pt` 权重只用于离线验证和导出，不直接进入 `ssvinfer` 运行时。

已完成的主要改动：

- 新增 `scripts/model/verify_helmet_models.py`，用于加载 `models/comp-*.pt`、读取模型 `names`、可选执行图片或视频源推理，并可将选定 `.pt` 导出为 ONNX。
- 新增 `config/model-labels/coco80.txt` 和 `config/model-labels/helmet.txt`。其中安全帽模型类别顺序为 `helmet`、`head`，与本次验证的 `.pt` 模型一致。
- 选定 `models/comp-2-freeze10.pt` 作为工程接入模型，并导出 `models/comp-2-freeze10.onnx`。
- `ssvinfer` 增加 `label-map` 属性，检测类别名从固定 COCO 表扩展为运行时类别表；`target-class` 为空时输出全部类别。
- `ssvinfer` 增加对 Ultralytics ONNX Nx6 输出的解析，支持 `(1, 300, 6)` 格式。
- `ssvinfer` 增加 `runtime`、`device`、`device-id`、`precision`、`model-family` 和 `output-format` 通用属性，支持 ONNX Runtime 与后续 TensorRT 后端解耦。
- `scripts/build.sh` 和 `scripts/lib.sh` 支持 `SSV_ONNXRUNTIME_FLAVOR=cpu|gpu`，CPU 和 GPU 版 ONNX Runtime 分别放在 `.deps/onnxruntime` 和 `.deps/onnxruntime-gpu`。
- `scripts/lib.sh` 会自动发现 uv 虚拟环境中的 NVIDIA wheel 动态库目录，解决 GPU 版 ONNX Runtime 找不到 CUDA/cuDNN 运行库的问题。
- `scripts/pipeline.sh` 已从 YAML 配置读取模型、类别表、目标类别、推理设备和运行时配置并传入 `ssvinfer`。
- 修复 `./ssv run --display` 在 X11/GTK 显示环境下可能无法弹窗的问题：脚本内部显示开关改为 `SHOW_DISPLAY`，避免覆盖系统 `DISPLAY` 环境变量。

本次排查中确认的关键结论：

- 看到 `nvh264dec` 或 `GstCudaContext` 只能说明视频解码使用了 GPU，不代表模型推理使用 GPU。
- 判断模型推理是否使用 GPU，应看 `ssvinfer` 的 active provider 日志；YAML 配置中 `inference.device: "gpu"` 会要求 GPU provider 可用，不可用时启动失败。
- `gtksink` 可使用统一 tee 显示链路；不需要为 `gtksink` 长期保留单链路显示特例。

## 推理设备

默认推理配置在 YAML 中表示为：

```yaml
inference:
  runtime: "auto"
  device: "auto"
  device_id: 0
  precision: "auto"
```

`runtime=auto` 会根据模型后缀选择后端：`.onnx` 使用 ONNX Runtime，`.engine` 使用 TensorRT。`device=auto` 在 ONNX Runtime 下优先尝试 GPU provider，不可用时回退 CPU；`device=gpu` 要求 GPU provider 可用，否则启动失败。日志会打印 runtime、active device 和 provider，用来区分 GPU 视频解码与 GPU 模型推理。

使用 GPU 推理时先切换 ONNX Runtime GPU 包并重新构建：

```bash
SSV_ONNXRUNTIME_FLAVOR=gpu ./ssv build
```

生产环境如果必须使用 GPU，可在 `config/ssv.yaml` 设置：

```yaml
inference:
  runtime: "onnxruntime"
  device: "gpu"
  device_id: 0
```

此时 GPU provider 不可用会导致 pipeline 启动失败，避免静默回退 CPU。

如果只想观察全部类别，将 `target_class` 设为空字符串：

```yaml
inference:
  target_class: ""
```

## 常见失败

- `.pt` 直接写入 `inference.model_path`：`ssvinfer` 会通过 ONNX Runtime 加载，不能识别 PyTorch 权重。
- `label-map class count mismatch`：ONNX 输出类别数与 label map 行数不一致，需要检查导出模型和类别表是否配套。
- `target-class not found in label-map`：`inference.target_class` 不在当前类别表中，需要使用类别表里的原始英文类别名。
- 缺少 `ultralytics`：离线验证脚本无法加载 `.pt`，需要先安装 Python 推理依赖。
- `CUDAExecutionProvider unavailable`：当前 ONNX Runtime 包不是 GPU 版，或 NVIDIA driver、CUDA、cuDNN 运行时不匹配。`inference.device: "auto"` 时会回退 CPU；`inference.device: "gpu"` 时启动失败。
