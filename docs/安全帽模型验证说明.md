# 安全帽模型验证说明

## 模型文件

本阶段验证 `models/comp-*.pt`。这些文件是 Ultralytics/PyTorch 权重，不能被 `ssvinfer` 直接加载。

现有工程实时链路通过 `ssvinfer` 和 ONNX Runtime 加载 ONNX 模型。安全帽 `.pt` 需要先完成离线验证，再导出 ONNX 后接入工程 smoke。

## 离线验证

先安装模型 extra：

```bash
python -m pip install -e ".[model-export]"
```

只验证模型能加载并读取类别表：

```bash
./ssv model verify --models-dir models
```

带图片或视频源验证：

```bash
./ssv model verify --models-dir models --source /path/to/validation/images
```

输出摘要默认写入：

```text
artifacts/model-verification/helmet-model-summary.json
```

## 实施结果总结

本次 T2 安全帽模型验证与接入计划已完成工程落地。原实时链路确认仍以 ONNX Runtime 加载 ONNX 模型，`models/` 下的 `.pt` 权重只用于离线验证和导出，不直接进入 `ssvinfer` 运行时。

已完成的主要改动：

- 新增 `scripts/model/verify_helmet_models.py`，用于加载 `models/comp-*.pt`、读取模型 `names`、可选执行图片或视频源推理，并可将选定 `.pt` 导出为 ONNX。
- 新增 `config/model-labels/coco80.txt` 和 `config/model-labels/helmet.txt`。其中安全帽模型类别顺序为 `helmet`、`head`，与本次验证的 `.pt` 模型一致。
- 选定 `models/comp-2-freeze10.pt` 作为工程接入模型，并导出 `models/comp-2-freeze10.onnx`。
- `ssvinfer` 增加 `label-map` 属性，检测类别名从固定 COCO 表扩展为运行时类别表；`target-class` 为空时输出全部类别。
- `ssvinfer` 增加对 Ultralytics ONNX Nx6 输出的解析，支持 `(1, 300, 6)` 格式。
- `ssvinfer` 增加 `runtime`、`device`、`device-id`、`precision`、`model-family` 和 `output-format` 通用属性，支持 ONNX Runtime 与后续 TensorRT 后端解耦。
- Python dependency service 统一准备 ONNX Runtime；CPU 使用版本 `1.25.1`，GPU 使用 `1.25.1-gpu`，两者共享稳定 ROOT `.deps/onnxruntime`。
- GPU 版 ONNX Runtime 所需 CUDA/cuDNN 由系统动态链接器或用户显式 `LD_LIBRARY_PATH` 提供，项目不扫描 Python NVIDIA wheel 目录。
- `./ssv run` 通过 C++ runner 从 YAML 配置读取模型、类别表、目标类别和推理 runtime，并传入 `ssvinfer`。
- `./ssv run --display` 通过 runner 参数控制显示，不覆盖系统 `DISPLAY` 环境变量；兼容路径可显式使用 `--display-backend gtksink`。

本次排查中确认的关键结论：

- 看到 `nvh264dec` 或 `GstCudaContext` 只能说明视频解码使用了 GPU，不代表模型推理使用 GPU。
- 判断模型推理是否使用 GPU，应看 `ssvinfer` 的 active provider 日志；YAML 配置中 `inference.runtime.providers` 可固定 Provider 链，不可用时启动失败。
- `gtksink` 可使用统一 tee 显示链路；不需要为 `gtksink` 长期保留单链路显示特例。

推荐的安全帽模型运行配置写入 `config/ssv.yaml`：

```yaml
inference:
  model:
    path: "models/comp-2-freeze10.onnx"
    label_map: "config/model-labels/helmet.txt"
    family: "yolo"
    output_format: "yolo_nx6"
  runtime:
    type: "onnxruntime"
    providers:
      mode: "auto"
    device_id: 0
    precision: "auto"
  target_class: ""
```

GPU 版 ONNX Runtime 由构建 profile 选择，使用 `./ssv build --profile nvidia` 重新构建。

使用以上配置后运行：

```bash
./ssv build
./ssv run --display
```

## 推理设备

默认推理配置在 YAML 中表示为：

```yaml
inference:
  runtime:
    type: "onnxruntime"
    providers:
      mode: "auto"
    device_id: 0
    precision: "auto"
```

`inference.runtime.type` 选择后端：`.onnx` 使用 `onnxruntime`，`.engine` 使用 `tensorrt-engine`。ONNX Runtime 的 `providers.mode: "auto"` 使用构建 profile 的默认 Provider 链；需要固定顺序时改为 `explicit` 并填写非空的 `order`，可用值为 `tensorrt`、`cuda`、`openvino`、`migraphx` 和 `cpu`。日志会打印 runtime、active device 和 provider，用来区分 GPU 视频解码与 GPU 模型推理。

使用 NVIDIA GPU 推理时先选择 NVIDIA profile 并重新构建：

```bash
./ssv build --profile nvidia
```

生产环境如果必须使用 GPU，可在 `config/ssv.yaml` 设置：

```yaml
inference:
  runtime:
    type: "onnxruntime"
    providers:
      mode: "explicit"
      order: ["tensorrt", "cuda", "cpu"]
    device_id: 0
```

显式 Provider 顺序中的 GPU provider 不可用时 runner 启动失败，不会静默改用其他 Provider。

如果只想观察全部类别，将 `target_class` 设为空字符串：

```yaml
inference:
  target_class: ""
```

## 常见失败

- `.pt` 直接写入 `inference.model.path`：`ssvinfer` 会通过 ONNX Runtime 加载，不能识别 PyTorch 权重。
- `label-map class count mismatch`：ONNX 输出类别数与 label map 行数不一致，需要检查导出模型和类别表是否配套。
- `target-class not found in label-map`：`inference.target_class` 不在当前类别表中，需要使用类别表里的原始英文类别名。
- 缺少 `ultralytics`：离线验证脚本无法加载 `.pt`，需要先安装 Python 推理依赖。
- `CUDAExecutionProvider unavailable`：当前构建 profile、NVIDIA driver、CUDA 或 cuDNN 运行时不匹配。检查 `inference.runtime.providers.mode`、Provider 顺序和 `./ssv build --profile nvidia` 的依赖快照。
